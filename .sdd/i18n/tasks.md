# Tasks · i18n

**Conventions**
- Paths: `lib/`, `test/` and `tool/check_layers.sh` are in `apps/bodega/`, where the app's commands run; `engine/` is `packages/engine/`, where `dart` runs; other paths, `tool/version.sh` and `tool/smoke_linux.sh` included, start at the repo root. The new `*_text.dart` files go in `lib/app/shared/text/` (design §6). **(USER)**: only the user can do it, on a real Mac or Linux box.
- Line numbers in the specs, the design and these tasks predate M1 and M2, and are off by about ten in places: match by content. Only T35's and the items T29 got from M2 were read after M2; the ones added after M3 are current.
- Every task ends green. Its **Check** names what is new, on top of `flutter analyze && flutter test && tool/check_layers.sh` in `apps/bodega` and, when the engine changed, `dart analyze && dart test` in `engine/`. Run `flutter gen-l10n` after an ARB edit, and build_runner after a Freezed or Injectable one.
- Moving text (design §3): each key goes into both ARBs, with its `@key` in `app_en.arb`; `const` goes, word tables become functions of `AppL10n`, `XTypeGroup` labels are built in the handler, and `context.l10n` is read before an `await`. The task's tests find English, reach Spanish only through `lookupAppL10n`, point their `findsNothing` at keys, and lose their Spanish fixtures (design §9).
- Turning engine text into a code (design §4 to §6): the engine gives it an English text with a case in `engine/test/english_test.dart`, the CLI prints that text, and `lib/app/shared/text/` words the code with a case in `test/app/text_test.dart`.
- The agent never commits or pushes. The user commits each milestone from a script the agent leaves (design §11), and the first commit needs T30.
