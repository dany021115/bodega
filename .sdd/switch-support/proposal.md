## Why
- Bodega runs Windows games only, each in a Wine bottle (`packages/engine/lib/apps.dart:6-15`), and the user wants Nintendo Switch games too. On Apple Silicon they run natively through an emulator the user installs: no Wine, no bottle, no Rosetta.
- Ryubing is the one emulator whose own project calls its Mac support proper; Eden's Mac builds are experimental (exploration §2). Linux comes later, so a second emulator and a second host must arrive as data and one class, not new logic.
- Bodega is public on GitHub under the GPL-3.0-or-later (`.claude/CLAUDE.md:3`), with its releases and update check there (`AGENTS.md:15-18`). Nintendo's 2026 notices target repositories that "offer, link to, or otherwise provide access to" Switch emulators, and GitHub applies them to whole fork networks (exploration §3). The law shapes this change as much as the code: Bodega finds what the user installed and checks that files exist, and never ships, downloads, reads or decrypts an emulator, keys, firmware or games; of all of them it links only to the emulator's official download page, which the user opens in the browser (17 U.S.C. §1201; *Nintendo of America v. Tropic Haze LLC*, D.R.I. No. 1:24-cv-00082).

## What
**In**
- On the Mac, Bodega finds Ryubing (`Ryujinx.app`) in `/Applications`, then `~/Applications`, then the `.app` the user picked, each confirmed by its `Info.plist`. It reports the version, whether macOS's quarantine attribute is on the app, and whether the emulator's key file and firmware folder exist. It reads no file's content and never strips the quarantine.
- A list of Switch games kept as absolute paths in `$BODEGA_HOME/switch/games.json`, added from files or from a folder scanned once, each titled from its file name, with the bracketed title id when there is one. Game files are never copied or opened.
- A game launches with the user's emulator, by default headless and full screen (`--no-gui --use-main-config --fullscreen`), in an environment of its own, with a log per run, a pid that survives a Bodega restart, and a Stop that signals the emulator.
- Native apps: Switch games the user made into Mac apps with nxnative (MIT), which is not an emulator: it rewrites a game's own code to run on the Apple chip. On the Mac, a `.app` whose `Contents/Info.plist` has `DMTitleID` joins the same list, from a file pick, `bodega switch add` or a folder scan, which checks a `.app` it meets and never goes inside it; one without `DMTitleID` is refused, with a code and words of its own. Its title comes from its file name, and its kind from its path, so the store does not change. It launches as its own executable (`CFBundleExecutable`, nxnative's launcher) with no arguments, in the emulator's environment whitelist and nothing more, so its own settings window keeps its settings; it has the same log per run, pid, follow, Stop and runs found again, and it needs no Ryubing. Its card shows a "Native" chip, and its quarantine attribute is reported like the emulator's and never stripped. On Linux, adding one fails as the emulator functions do.
- A "Switch" section in the app on hosts that support it (the Mac): a status panel, the game grid, "Add games", "Choose Ryubing…" and a full-screen switch, in English and Spanish. While Ryubing is missing, the panel says so and why Bodega needs it, and offers "Download Ryubing", which opens its official download page in the browser, with a line on what to do after: put `Ryujinx.app` in Applications, then click "Check again". The Library, its bloc and Wine's launch path stay as they are.
- `bodega switch status|emulator|option|add|list|remove|open|stop`, outside the `checkHost` gate: Rosetta is a Wine need (`packages/engine/bin/bodega.dart:245-251`). With no emulator found, `status` names its download page and the next steps.
- Room for Eden and Linux: an emulator table with per-OS sub-records, one `HostPlatform` getter that returns an emulator host (real on the Mac, a "not yet" stub on Linux), and one capability, false on Linux.
- New lines not to cross in `.claude/CLAUDE.md`, nxnative's among them, a README item that names the emulator and nxnative without a link, and a test that fails on a URL in the Switch code, the ARBs, or the paragraphs of the docs that name Switch, its emulators or nxnative, but for the emulator's download page in the emulator table.

**Out**
- Eden, Linux and Flatpak (the second phase); Hydra, Kenji-NX, Citron and the other forks; Windows hosts and arm64 Linux.
- Any download, bundle or install command for an emulator, keys, firmware or games; any link to them but the emulator's official download page; and any text on how to get keys, firmware or games or how to make an nxnative app. Installing keys or firmware stays in the emulator's own menus; Bodega never runs `--install-firmware`.
- Titles or art from inside the files, online metadata (IGDB, ScreenScraper), titledb data, eShop images, `.nro` icons, emulator caches, covers the user picks, play time.
- Input profiles, the emulator per game, docked or handheld mode, the emulator's data folder (`-r`).
- Switch games in the Library (exploration C3), Switch without the Wine runtime (the setup gate stays, exploration Q3), a log viewer for Switch runs.
- Package text and file types: `packaging/linux/bodega.desktop:4`, `packaging/linux/build_deb.sh:38` and `packaging/arch/PKGBUILD:8` stay, with no `MimeType=`.
- From nxnative: building apps with it or running any of its scripts; `prod.keys` for it, which Bodega never asks for, finds or passes; iPhone and iPad IPAs; its settings list (`launcher.json`), saved choices, cheats, cloud saves, `env.txt` and `DM_` variables; its icon (`AppIcon.icns`); words of their own for its exit codes 70 and 134, beyond what the log and the usual "exited" notice give.

## Impact
- Engine and CLI: new `packages/engine/lib/switch.dart` behind one more `part` line (`engine.dart:14-21`); a getter on `HostPlatform` (`platform.dart:18-78`) and a capability field (`:7-16`), one line each in `platform_mac.dart` and `platform_linux.dart`; a `switch` case, usage lines and a gate condition in `bin/bodega.dart`. The emulator host also reads native apps (`nativeApp`), and the two functions that add take the host as an argument, for isolates. Wine's code is untouched: `_launch`, `_start`, `_newLog`, `apps.json`, `InstalledApp`.
- App: five `AppError` codes with their `appErrorOf` and `error_text.dart` cases; `HostCapabilities.switchGames`; new `switch_game.dart` (with `native` and `quarantined`), `switch_status.dart`, `switch_repository.dart` and its implementation; `lib/app/bloc/switch/`; `lib/app/presentation/switch/`; `lib/app/shared/text/switch_text.dart`; edits to `router.dart`, `manager.dart`, `side_bar.dart`, `main.dart` and `shell_body.dart`; `AppCard` gains a constructor that takes fields instead of a `LibraryApp`; 27 keys per ARB.
- Tests: new engine `switch_test.dart` and `switch_links_test.dart` with a fake emulator and a fake native app, both scripts; repository and bloc tests; the panel's download button against a fake `url_launcher` platform (`url_launcher_platform_interface`, a new dev dependency already in `pubspec.lock`); the Switch page in `pages_test.dart`; the side bar in `main_shell_test.dart`; text and parity cases. No real emulator, keys, firmware, games or native apps in git or CI, and no new CI job.
- Docs: `.claude/CLAUDE.md`, `AGENTS.md:3`, `.claude/rules/architecture.md`, `README.md`.
- Users: on the Mac, a Switch item under Library, where native apps made with nxnative play too, and a way to the emulator's download page while it is missing; on Linux nothing changes. Bodega downloads nothing, and the data root gains `switch/` the first time Switch is used.

## Risks
| Risk | Mitigation |
|---|---|
| A DMCA notice takes the repo, and with it the Wine recipe, the releases and the update check (exploration §3) | nothing ships or downloads; the one link is the emulator's official download page, which only the emulator table holds, and a test fails on any other URL; neutral text; Switch in one engine file and one app folder; GitHub contacts owners before acting |
| A link or a how-to reaches public text: ARB descriptions, the README, PR titles that become release notes (`release-linux.yml:179`, `release-macos.yml:167`) | the link guard, whose words include nxnative; copy names what is missing and, of the emulator alone, that its official download page opens, never where to get keys, firmware or games or how to make an app; no URL in any ARB, doc, commit or pull request; the new rules in `.claude/CLAUDE.md` |
| Wine's environment reaches the emulator, such as `DOTNET_EnableWriteXorExecute=0` (`platform_mac.dart:90`) for a .NET program | a per-host whitelist with no Wine or .NET keys, tested like `wineEnv` |
| A Stop that leaves tracking hanging, or a reused pid after a restart (`engine.dart:355-356`) | the emulator is signalled, never the shell; a `.pid` beside the log and a command-line check |
| Headless lacks something users need, or the process outlives the game | `headless` is a saved setting; the USER check decides the default; the normal UI with `--fullscreen`, as other frontends run it, is the fallback |
| TCC prompts in Bodega's name, since the emulator or a native app is its child | a USER check; usage strings in both languages if prompts show; `open -W` only if games break |
| A quarantined emulator or native app that was never opened won't start | the status reports the attribute and the panel says to open it once from the Finder and, if macOS blocks it, to allow it in System Settings > Privacy & Security; Bodega never strips it |
| A folder scan floods the list: content archives, huge folders, protected folders | `.nca` skipped in scans, two levels deep, no links, no hidden folders, a `.app` checked and never listed; picked files are taken as they are |
| Collisions with i18n | none left to meet: i18n reached `main` whole as `v1.5.0` (pull request #13) before M1 was committed, and the branch started from `main` right after it, at 7ef6006, which adds only i18n's docs, so no rebase follows; it now starts from `v1.5.1` (cfd3e10), whose fix tracks the Library's runs per app and touches no Switch file; the side bar already holds i18n's language item (`language_menu.dart`), which the 480 px test keeps beside Switch, the version counts from `v1.5.1`, and the `checkHost` gate that SE22 wraps in `needsHost(args)` is already i18n's T35(d) form (`packages/engine/bin/bodega.dart:247-257` at `v1.5.0`), whose check T12 runs on M1 |
| The side bar at 480 px (`widget-standards.md:29`) | one item; `main_shell_test.dart` at 801×480 with Language and Switch |
| Emulator internals change: paths, flags | a table, pinned in tests; only the game path and three flags; the user's pick |
| nxnative has no releases or tags and changes fast: a front end pins a commit (its front-end guide) | Bodega relies only on `DMTitleID`, `CFBundleExecutable` and its launcher's exit codes and signals, pinned by tests with a fake app, plus the USER check with an app the user made; nothing of nxnative's settings, files or scripts |
| Stop's SIGKILL, 5 s after the SIGTERM, reaches only nxnative's launcher, which cannot forward it, so the game's host would stay | the launcher forwards the SIGTERM that comes first; the USER check sees Stop close the game, and if it does not, native runs get no SIGKILL |
| Picking a `.app` with `file_selector` is untested (exploration §5), for the emulator and now for native apps through "Files…" | a USER check; `bodega switch emulator <path>` and `bodega switch add <app>` |

## Version
**Decision (the user, 2026-11-10, exploration Q17): 1.6.0**, the minor after i18n's 1.5.0 (`AGENTS.md:8`; `.sdd/i18n/proposal.md` §Version), on its own branch, `feat/switch-support`, taken from `main` at 7ef6006, i18n's docs on top of `v1.5.0`, and moved on 2026-11-11 onto `main` at cfd3e10, `v1.5.1`, which carries `1.5.1+13`. `tool/version.sh` counts from the last tag reachable from `HEAD` (`tool/version.sh:31-33`), `v1.5.1` now, so `check` refuses M1's product changes while the version is still 1.5.1 (`:86-95`). The bump (`bump minor`, `:46-72`: `1.5.1+13` → `1.6.0+14`; it was `1.5.0+12` → `1.6.0+13` on 7ef6006) is therefore the branch's first commit, of the `version:` line alone, which `../switch-commit.sh` makes before M1's commit, reading both `version:` lines, `HEAD`'s and the working tree's, instead of fixed numbers; the lead ran it in the branch's working tree on 2026-11-11, and `check` then printed `OK: version 1.6.0 (tag v1.5.1).` M1's, M2's and M3's commits carry `1.6.0+14`, which a later `bump minor` leaves as it is (`:66-69`). No tag is created, moved or deleted by hand (`AGENTS.md:16`).
