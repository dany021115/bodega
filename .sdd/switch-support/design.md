# Design · switch-support

Paths: `lib/` and `test/` are `apps/bodega/lib/` and `apps/bodega/test/`; `engine/` is `packages/engine/`; other paths start at the repo root. Bare Dart file names are unique in the repo. Line numbers are today's, with i18n's M1 committed (60e545a); i18n's M2 rewrites the engine's throws and `data/`'s errors before this change applies, so where this design builds on M2 it cites `.sdd/i18n/design.md`. Ryubing is the project and `Ryujinx.app` its Mac app. Facts about Ryubing come from its own sources at commit `a61a426` (MIT), named by file and never linked (exploration §2). Facts about nxnative, which makes Mac apps of a user's own games (§4), come from its own guides at commit `0d84a3f7bc24` (MIT), named the same way and never linked.

## 1. The engine part
- New `engine/lib/switch.dart`, a `part of 'engine.dart'` behind one more `part` line (`engine.dart:14-21`), like `gamepads.dart`. It holds the emulator table, the store, the settings, the status, the scan, the native apps' checks (§4), the launch, the CLI's verb grammar and helpers (§8), the five failures of §6 (a sealed class's subclasses may live in any part of its library) and the emulator hosts of §7, so removing Switch is deleting this file and the few lines that name its types. Wine's `_launch`, `_start`, `_newLog`, `apps.json` and `InstalledApp` stay as they are (exploration Q9, Q10).
- Types, records like the engine's others (`apps.dart:6-15`, `backends.dart:389-410`):
  ```dart
  /// One emulator, as data: Eden and Linux arrive as a row and a sub-record.
  typedef Emulator = ({
    String id,               // 'ryubing', the row's key
    String name,             // 'Ryubing', a brand shown as is
    String page,             // its official download page, the one link held
    List<String> extensions, // what it opens: lower case, no dot
    EmulatorArgs args,
    EmulatorOnMac? mac,
    EmulatorOnLinux? linux,  // null until the second phase
  });
  typedef EmulatorArgs = ({List<String> headless, List<String> fullscreen, List<String> game});
  typedef EmulatorOnMac = ({String bundleId, String app, String executable, EmulatorFiles files});
  typedef EmulatorOnLinux = ({List<String> appImages, String? flatpak, List<String> commands, EmulatorFiles files});

  /// `~` is HOME, `<bin>` the executable's folder, `<dir>` the folder that holds
  /// the install, `<data>` the data folder in use. The last `data` entry is the
  /// default one.
  typedef EmulatorFiles = ({List<String> data, String keys, String? userKeys, String firmware});

  /// [path] is the key: absolute, as the picker or the scan gave it.
  typedef SwitchGame = ({String path, String title, String? titleId, DateTime added});
  typedef SwitchSettings = ({String? picked, bool fullscreen, bool headless});
  ```
- The table, `const switchEmulators`, has one row in the MVP. Its `page` is Ryubing's official download page, which the user asked for on 2026-11-11 (proposal.md): the one link of an emulator in the repo, held by this row alone (tests may name it, §11), which the CLI's status names and the app opens in the browser while no install is found (§8, §9), as D3DMetal's section opens Apple's page from `gptkReleases` (`backends.dart`, I1); Bodega never downloads, bundles or installs the emulator itself. The table's comment names the sources below, as `catalog_data.dart:1-3` names its own:

| Field | Ryubing on the Mac | Read in (at `a61a426`) |
|---|---|---|
| `extensions` | `xci nsp pfs0 nca nro nso` | `src/Ryujinx/Systems/AppLibrary/ApplicationLibrary.cs` |
| `args` | headless `--no-gui --use-main-config`; fullscreen `--fullscreen`; game `{game}` | `src/Ryujinx/Utilities/CommandLineState.cs`, `src/Ryujinx/Headless/Options.cs` |
| `mac` | `org.ryujinx.Ryujinx`, `Ryujinx.app`, executable `Ryujinx` | `distribution/macos/Info.plist`, `create_app_bundle.sh` |
| `files.data` | `<bin>/portable`, `<dir>/portable`, `~/Library/Application Support/Ryujinx` | `src/Ryujinx.Common/Configuration/AppDataManager.cs` |
| `files.keys`, `userKeys` | `<data>/system/prod.keys`; `~/.switch/prod.keys`, which counts only with the default data folder (Ryubing's normal mode) | `src/Ryujinx.HLE/FileSystem/VirtualFileSystem.cs` |
| `files.firmware` | `<data>/bis/system/Contents/registered` | `ContentManager.cs`, `ContentPath.cs` |

- Storage, made on demand under the data root, as `backends/` is (`backends.dart:290`); `bodegaHome` (`engine.dart:33-35`) is not touched:
  - `$BODEGA_HOME/switch/games.json`: `{"games": [{"path", "title", "titleId"?, "added"}]}`. Paths only, never a copy or anything read from a file; a native app's entry is the same, its kind following from its path (§4). `added` is an ISO UTC date, like `installedAt` (`apps.dart:124`). Q9's `inLibrary` comes with C3: an entry without it reads as in the Library, so no file changes then. A rewrite keeps each entry as it was read, keys the engine does not know included.
  - `switch/settings.json`: only what differs from the defaults (no pick, full screen, headless), as `_saveSettings` writes (`backends.dart:519-543`), so a default the USER check changes (§13) reaches everyone who never set it. Q15's emulator key comes with Eden's row: a file without it reads as Ryubing, so no file changes then. A rewrite holds the three known keys only, as `_saveSettings`'s does.
  - `switch/logs/<UTC>-<label>.log`, with its `.pid` and `.exit` beside it (§5).
  - Every write goes through `_writeJson` (`backends.dart:512-517`), atomic. A file that does not parse throws `CorruptData(source, detail)`, with that file as `source` (i18n design §4), as `apps.dart:62` does today.

## 2. Detection on the Mac
- `MacEmulators.find(emulator, env, {picked})` tries, in this order (exploration Q14):
  1. `/Applications/Ryujinx.app`;
  2. `$HOME/Applications/Ryujinx.app`, with `HOME` from the env map, as `defaultHome(env)` takes it (`platform.dart:39`), never from `Platform.environment` (`platform_linux.dart:27` does);
  3. `settings.picked`.

  The first confirmed one wins. A pick never overrides a copy in the fixed places: the panel offers "Choose Ryubing…" only while they hold none or the install in use is the pick, and it always shows the path in use. No Spotlight (`mdfind`): it can be off, and it lists copies on disk images and other volumes.
- Confirmed means: `<app>/Contents/Info.plist` has `CFBundleIdentifier` equal to the row's `bundleId` and `CFBundleExecutable` equal to its `executable` (Eden's id is old yuzu's, so the id alone would not tell them apart, exploration §2), and `Contents/MacOS/<executable>` is a regular file with an exec bit, the test `_onPath` makes (`platform_linux.dart:290-299`). `CFBundleShortVersionString` gives the version, or null. Each key is one `/usr/bin/plutil -extract <key> raw <plist>`, as `d3dmetalVersion` reads one (`backends.dart:95-107`); a failure or an empty value means "not this candidate", never an error.
- `EmulatorInstall = ({String app, String exe, String? version, bool picked, bool quarantined})`.
- Quarantine: `/usr/bin/xattr -p com.apple.quarantine <app>` exits 0 when the attribute is there. Bodega reports it and never removes it; `_stripQuarantine` (`platform_mac.dart:275-282`) and `afterExtract` (`:114-117`) stay for Bodega's own copies only. The attribute stays after the user approves the app once (macOS then sets an approval flag in its value), so it does not mean blocked: the panel words it as a quiet conditional note (§9), and the USER check (§13) sees what a never-opened copy does. A native app's attribute is read the same way, by `nativeApp` (§7), shown as the emulator's is (§8, §9) and never removed: nxnative signs its apps ad hoc unless they were packed with another identity, and never notarizes them (§4).
- The pick: `chooseEmulator(home, app)` confirms `app` with `MacEmulators.confirm` and saves it, or throws `NotAnEmulator`; `null`, the CLI's `auto`, forgets it.
- Seams, so the tests run on Linux CI: `MacEmulators({String root = '', plistKey, quarantine})`, where `root` prefixes `/Applications`, `plistKey` replaces `plutil` and `quarantine` replaces `xattr`, for the emulator and for native apps alike. The real tools are tested on the Mac only and skipped elsewhere, as `backends_test.dart:423` does.

## 3. The status report
- `Future<SwitchStatus> checkSwitch(String home, [Map<String, String>? env])`, a facade beside `checkGamepads` (`engine.dart:93-95`), with `env ?? Platform.environment`:
  ```dart
  typedef SwitchStatus = ({
    Emulator emulator,        // the table's one row
    EmulatorInstall? install, // null: not found
    bool keys,
    bool firmware,
  });
  ```
- The data folder in use is the first entry of `files.data` that exists. `keys`: `<data>/system/prod.keys` exists, or `~/.switch/prod.keys` exists while that folder is the default entry or none exists. `firmware`: `<data>/bis/system/Contents/registered` exists and holds at least one entry, asked as `Directory.list().isEmpty`, which stops at the first name; a folder Bodega may not list counts as empty.
- Existence checks only, at the paths of the row: `FileSystemEntity.typeSync` and that one listing. Never an `open`, a read, a size or a hash; an empty `prod.keys` counts as present.
- It never blocks the rest of Bodega, like the gamepad report (`gamepads.dart:14-21`): it is not in `checkHost` (`platform.dart:46`), `RuntimeStatus` or `setupRedirect` (`router.dart:41-49`), and a launch checks only that the emulator is there for a game file, and nothing of it for a native app (§5). Where the host has no support it throws `NotAvailable('switch', host)` (i18n design §4).

## 4. Adding games
- `addSwitchGames(home, paths)` takes files and native apps (below); `addSwitchFolder(home, folder)` scans a folder once and adds what it finds. Both return `({int added, int known})`, `known` counting paths already in the list, and write `games.json` only when a path is new. There is no re-scan, so there is no `hidden` list (exploration Q16).
- Extensions: the row's, Ryubing's six, compared without case. A picked path with another extension throws `NotASwitchGame`, and so does one with a game's extension that is not a file, such as a folder named `x.nsp`; `MissingFile(path)` is only for nothing there (i18n design §4; `apps.dart:143` today), as for a `.app`, which is a native app's path, checked as below.
- The scan reads names only: the folder and two levels below it, following no link (as `_shortcutFiles` does, `apps.dart:254-279`), skipping hidden entries, checking each bundle (`*.app`) as below and never listing one, and skipping `.nca`, since an unpacked title holds many content archives, each a part rather than a game. A `.nca` picked by hand is taken. The depth also bounds a scan of a too-wide folder. The folder given is the one link the scan follows: a link to a folder is scanned, nothing inside it is followed, and its games are kept under the link's path. A path where no folder is, nothing or a file, throws `MissingFile(folder)`; a folder given that Bodega may not list adds nothing and throws nothing, as one below it is passed over, so a folder macOS denies looks empty (the USER check, §13, sees what the page shows then); and a folder given that is itself an app is checked as an app the scan meets, never listed inside.
- The store's functions (these two, `switchGames(home)` and `removeSwitchGame(home, path)`) never touch `hostPlatform` and work on any host, but for a `.app`: the two that add take an optional `emulators` and ask it, or else `hostPlatform.emulators`, about each `.app` they meet. So `data/` can run them in `Isolate.run`, as `apps()` runs (`library_repository_impl.dart:19-25`), passing in the `engine.hostPlatform.emulators` it read before the call, and they behave the same in a test, where the isolate's globals start fresh: `MacEmulators` holds a path and two functions, which an isolate of the same group receives. The functions that need the emulator (`checkSwitch`, `chooseEmulator`, `openSwitchGame`, `stopSwitchGame`, `switchRuns`) throw `NotAvailable` where the host has no support.
- Title: the file name without its extension, without every `[…]` and `(…)`, with runs of spaces and `_` as one space, trimmed; the file name if nothing is left. Title id: the first bracketed block of exactly 16 hex digits, upper-cased (Eden prints ids as `{:016X}`, exploration §2). `Bodega Test [0100F00DBA5E0000][v0] (EU).nsp` gives `Bodega Test` and `0100F00DBA5E0000`; a native app's `Bodega Test.app` gives `Bodega Test` and no id. The card shows the title's initial, as today for an app without an icon (`app_icon.dart:69-76`).
- `removeSwitchGame(home, path)` forgets the entry and never touches the file.
- **Native apps.** A Switch game the user made into a Mac app with nxnative (MIT) is listed and played like a game file, without the emulator. nxnative is not an emulator: it rewrites the game's own code to run on the Apple chip, emulates Horizon's services at a high level and runs NVN graphics on Metal; only games it has a profile for are known to run, 157 at commit `0d84a3f7bc24` (2026-11-10). It has no releases or tags, so its facts are those of that commit, in its front-end guide (`docs/frontends.md`, "Starting a game") and its development guide (`docs/development.md`, "A Mac app"). Bodega relies on two keys of the app's `Info.plist` and on its launcher's contract, and on nothing else of nxnative's:

| nxnative, at `0d84a3f7bc24` | Bodega |
|---|---|
| The app is `<game name>.app` by default (a `:` or `/` in the name becomes ` - `), with the bundle id `org.nxnative.<title ID>` unless it was packed with another | titles it from the file name, as a game file; uses no bundle id |
| `Contents/Info.plist` holds `DMTitleID`, the base game's title id, beside `DMSettings` and other keys for its launcher | takes a `.app` with `DMTitleID` as a native app, and writes it in the first line of its run's header (§5) |
| `CFBundleExecutable` is `Contents/MacOS/nxnative`, a launcher that runs `Contents/MacOS/dmhost` as its child, forwards SIGTERM, SIGINT and SIGHUP to it and exits with its code: 0 for a quit (Cmd-Q, the Home prompt, closing the window), 70 after macOS stopped the game's GPU work, 134 for an abort | starts it with no arguments; 0 is a normal end, and any other code takes the usual notice (§5, §9) |
| Before the game, the launcher shows its own settings window unless `DM_LAUNCHER=0`, and a variable already in the environment wins over `env.txt` and the saved choices | passes no `DM_` variable, so that window and the user's choices apply (§5) |
| The host's log is `~/Library/Logs/nxnative/<title ID>.log`, the previous run's `<title ID>.prev.log`; the save is in `~/Library/Application Support/nxnative/<title ID>/save/` | touches neither |
| The app is signed ad hoc unless packed with another identity, and is never notarized: on a Mac it was downloaded to, Gatekeeper blocks it until the user allows it in System Settings > Privacy & Security | reports its quarantine attribute as the emulator's (§2), with the same note |

- A path is a native app's when its name ends in `.app`, without case: `isNativeApp(path)`, the one rule the store, the scan, the launch, the CLI and `data/` share, so the store keeps no kind. Such a path holds a native app when the host's `nativeApp` (§7) reads `DMTitleID` from `<path>/Contents/Info.plist`, one `plistKey` read as in §2; nothing else makes or refuses one, and nothing of the app is read but §7's two keys and its quarantine attribute. `addSwitchGames` checks a `.app` path as it checks a file: `NotAvailable` where the host has no support, `MissingFile` when nothing is there, `NotASwitchGame` when `nativeApp` gives null. The scan checks each `*.app` it meets, the folder given included, the same way, adds it when it is one and never lists it; where the host has no support, it passes over every `*.app`, as it did, and throws nothing for them. The emulator's status says nothing of native apps.
- Bodega never builds a native app, never runs nxnative's scripts, and never asks for, finds or passes `prod.keys` for it (§12).

## 5. Launch and tracking
- `openSwitchGame(home, path, [env])` returns the run's log:
  1. It throws `NotAvailable` where the host has no support, `SwitchGameNotFound` for a path not in the list, `MissingFile` when the file is gone, `SwitchGameRunning` when a live run of it exists (`switchRuns`), and `NoEmulator` when `find` gives nothing.
  2. argv: `<app>/Contents/MacOS/<CFBundleExecutable>`, then `--no-gui --use-main-config` if headless, `--fullscreen` if full screen, then the game, from the row's `args`. Headless ends with its window (`HeadlessRyujinx.cs`), so `.exit` means the game ended, and `--use-main-config` keeps the settings the user made in Ryubing's window (exploration Q5).
  3. `cwd` is `$HOME` from the env map, or `/` when the map has none: Ryubing will not start from `~/Downloads` or iCloud (`src/Ryujinx/Program.cs`).
  4. The environment is the host's whitelist (§7), with `includeParentEnvironment: false` as in `_start` (`engine.dart:451-453`). On the Mac: `HOME`, `USER`, `LOGNAME`, `TMPDIR`, `__CF_USER_TEXT_ENCODING` and `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, the session part of `baseEnv` (`platform_mac.dart:79-87`) without its Wine and .NET keys (`:88-91`). Ryubing is .NET: `DOTNET_EnableWriteXorExecute=0` must not reach it.
  5. The log is `switch/logs/<UTC>-<label>.log`: the stamp as `_newLog` makes it (`engine.dart:565-569`, copied so Wine's function stays as it is), the label from the title as `_launchIn` makes one (`[A-Za-z0-9._-]`, at most 40, `:277-290`). Its header never holds the environment (R15): `# emulator Ryubing 1.3.3`, `# exe <executable>`, `# game <path>`, `# cwd <HOME>`, `# argv …`.
  6. It starts detached through a pid-writing variant of `_launch` (`engine.dart:429-434`) that keeps its contract (output appended to the log, `# exit=N`, `.exit` written atomically, no `exec`) and puts the program in the background, so the shell writes its pid before it waits:
     ```dart
     const _launchPid =
         r'l=$1; shift; "$@" >>"$l" 2>&1 </dev/null & p=$!; '
         r'echo "$p" >"$l.p" && mv -f "$l.p" "${l%.log}.pid"; '
         r'wait "$p"; s=$?; echo "# exit=$s" >>"$l"; '
         r'echo "$s" >"$l.x" && mv -f "$l.x" "${l%.log}.exit"; exit $s';
     ```
     `Process.start('/bin/sh', ['-c', _launchPid, 'bodega', log, ...argv], workingDirectory: HOME, environment: …, includeParentEnvironment: false, mode: ProcessStartMode.detached)`. It returns once the `.pid` exists, or throws `ProcessFailed` with the executable as `command`, no exit code, and the engine's own words as `output`: `could not start /bin/sh in <cwd>` when the start fails, since Dart 3.13 garbles its message for a detached start that fails (M1), or `no pid within 2 s`. A detached start gives a pid, never an exit code (exploration §4.1), so the `Process` is dropped as `_launchIn` drops its own (`engine.dart:321`): the files are the contract.
- A run is followed with Wine's `exitOf(log)` (`engine.dart:353-361`), as exploration Q10 says: Stop never signals the shell, so the shell writes `.exit`; a shell killed from outside Bodega leaves that wait open, as `exitOf` already accepts for Wine (`:355-356`).
- `switchRuns(home)` returns `List<({String game, String log})>`: each `.log` with a `.pid` and no `.exit` whose pid still runs its `# exe`, the `# exe` and `# game` read from the log's `# ` lines alone, up to the first other line and within its first 64 KiB, since a log grows with the emulator's output. That finds a run again after Bodega restarts; a pid that runs something else (reused) or nothing marks a run that ended.
- `stopSwitchGame(home, path)` acts on each live run of that path, listed or not: it has the host's `stop` send SIGTERM (`Process.killPid`, Dart's own, no `kill` tool), waits up to 5 s, one wait for them all, for their `.exit`, then calls `stop` with `kill: true` for each that has none while its pid still runs the `# exe`, and returns without waiting for the `.exit` the shell then writes. It never signals the shell, because a dead shell writes no `.exit` (`engine.dart:355-356`). A listed game with no live run is a no-op, as `stopBottle` takes "no server" (`:342-349`); a path with neither throws `SwitchGameNotFound`.
- The liveness check is `/bin/ps -ww -p <pid> -o command=` (in `/bin`, not `MacPlatform.tool`'s `/usr/bin`, `platform_mac.dart:108-109`): it exits 0 and its line contains the `# exe` path. `-ww` keeps the line whole: procps honours an exported `COLUMNS` even when its output is piped, which could cut the line and hide a live run. Dart has no signal 0 (exploration §4.1), and the command line carries the executable's path for the real emulator and for a test's script alike.
- Fallback, built only if the USER check (§13) finds TCC prompts that break games: `/usr/bin/open -W -n -a <app> --stdout <log> --stderr <log> --args …`, where `.exit` then holds `open`'s code and the pid is found by the executable's path. Prompts that show and work keep exec, with the usage strings they need added in both languages, in the `InfoPlist.strings` files i18n's T27 creates.
- A native app (§4) goes through the same steps, with four differences. Its last check is `nativeApp(path)` instead of `find`: null, or a null `exe`, throws `NotASwitchGame`, so it needs no emulator, keys or firmware. Its argv is `exe` alone, with no arguments, whatever `headless` and `fullscreen` say. Its environment is the same whitelist with nothing added, so no `DM_` variable reaches it and nxnative's own settings window and the user's choices apply (§4's table). Its header's first line is `# native <title ID>`, its `DMTitleID`, instead of `# emulator …`. The `.pid`, `.exit`, the wait, `switchRuns` and Stop are the same: the pid is the launcher's, which forwards SIGTERM to the game's host and exits with its code. A SIGKILL, 5 s after the SIGTERM, reaches only the launcher, which cannot forward it, so the host would stay: the USER check (§13) sees whether Stop closes the game within those 5 s, and if it does not, a native run gets no SIGKILL. If the USER check finds prompts that break native games, native runs take the `open -W` fallback above, with no `--args`.

## 6. Failures and codes
- Five final subclasses of `EngineFailure`, in `switch.dart` (§1), each with an English message that keeps a CLI hint, as i18n's do (i18n design §4), and a case in `engine/test/english_test.dart`. In the messages, `$x` is a field and `<x>` is what the user types:

| Subclass (fields) | Thrown by | Message | `AppError` |
|---|---|---|---|
| `NoEmulator(name, app)` | `openSwitchGame` | `$name not found: Bodega looks for $app in /Applications and ~/Applications, or takes one from bodega switch emulator <path>` | `noEmulator(name, app)` |
| `NotAnEmulator(path, name)` | `chooseEmulator` | `$path is not $name: its Info.plist names another app` | `notAnEmulator(path, name)` |
| `NotASwitchGame(path, extensions)` | `addSwitchGames`; `openSwitchGame`, for a native app | `$path is not a Switch game: .xci .nsp .pfs0 .nca .nro .nso, or an nxnative app` (the extensions) | `notASwitchGame(path)`: the picker takes any app bundle (§9), so a `.app` without `DMTitleID` reaches it from the app; the propose result mapped it to `unknown` |
| `SwitchGameNotFound(path)` | open, stop, remove | `$path is not among the Switch games: bodega switch list` | `switchGameNotFound(path)` |
| `SwitchGameRunning(path)` | `openSwitchGame` | `$path is already running: bodega switch stop "$path"` | `switchGameRunning(path)` |

- Reused from i18n: `MissingFile(path)` → `badPath(missing)`, `CorruptData` → `corruptData`, `NotAvailable('switch', host)` → `unknown` (the capability hides the section, as for D3DMetal), `ProcessFailed` → `processFailed`.
- `data/`: five factories join the `AppError` union (i18n design §5; `app_error.dart:7-12` today), each with `{String? detail}` and the fields of its subclass, but `notASwitchGame`, whose extensions stay in `detail`, as `processFailed` keeps a tool's output there. `appErrorOf` gains five cases and still has no default branch, so the build fails until each one is handled (i18n E12).
- Words, in `lib/app/shared/text/error_text.dart` (`AppError.localized(l10n)`, i18n design §6): `errNoEmulator(name, app)`, `errNotAnEmulator(path, name)`, `errNotASwitchGame(path)`, `errSwitchGameNotFound(path)` and `errSwitchGameRunning(path)`. They give GUI advice where the engine gives commands ("choose it on the Switch page", "Stop it first"), never `bodega switch …`. `detail` is never rendered, and error panels offer "Copy details" (i18n design §6).
- The bloc's notices are codes too (§9): `SwitchNotice.added(added, known)` and `SwitchNotice.exited(title, code)`, worded by an exhaustive switch in new `lib/app/shared/text/switch_text.dart`.

## 7. The HostPlatform hook
- One abstract getter on `HostPlatform`, beside `gamepads()` (`platform.dart:48-50`):
  ```dart
  /// Switch emulators on this host: found and started on the Mac, not yet on
  /// Linux.
  EmulatorHost get emulators;
  ```
  `MacPlatform` returns `const MacEmulators()` and `LinuxPlatform` `const LinuxEmulators()`, one line each. `TestMac` inherits it (`engine/test/_mac.dart:8`); a Switch test overrides it (§11). The classes live in `switch.dart`, which keeps Switch in one file while the system's code still hangs off the platform (`architecture.md:48-54`).
- The host:
  ```dart
  abstract class EmulatorHost {
    const EmulatorHost();
    bool get supported;
    Future<EmulatorInstall?> find(Emulator emulator, Map<String, String> env, {String? picked});
    Future<EmulatorInstall?> confirm(Emulator emulator, String path);
    /// A native app (§4), or null when its Info.plist has no DMTitleID.
    Future<NativeApp?> nativeApp(String app);
    EmulatorFiles? files(Emulator emulator);
    /// The whole environment of an emulator or a native app: nothing else
    /// from [parent].
    Map<String, String> env(Map<String, String> parent);
    Future<bool> runs(int pid, String exe);
    /// SIGTERM, or SIGKILL when [kill], through Process.killPid, and only
    /// while [pid] runs [exe].
    Future<void> stop(int pid, String exe, {bool kill = false});
  }
  ```
  `NativeApp = ({String titleId, String? exe, bool quarantined})`: `exe` is `<app>/Contents/MacOS/<CFBundleExecutable>` when that key reads, holds no `/`, so that the executable stays in `Contents/MacOS/`, and names a regular file with an exec bit, as `confirm` holds the emulator's to, else null; `quarantined` is §2's check. On the Mac each key is one `plistKey` read and the attribute one `quarantine` call (§2); a native app's path is used as given, never under `root`.
  `LinuxEmulators` is the "not yet" stub: `supported` is false, `find` gives null, and every other member throws `NotAvailable('switch', 'Linux')`.
  `EmulatorHost` has no name of its own: where the emulators given to an add (§4) are not supported, `NotAvailable` names its host through `hostPlatform.displayName`, as the functions that ask the host's own emulators do. `data/` passes the host's own (§9), so the name is right.
- The data table is §1's `switchEmulators`, and a host reads only its own sub-record (`mac`, `linux`), so a fork that renames its app is a table edit (exploration Q12).
- One capability: `HostCapabilities` gains `bool switchGames` (`platform.dart:7-16`), equal to `emulators.supported`: true on the Mac (`platform_mac.dart:132-142`), false on Linux (`platform_linux.dart:168-178`). The domain twin gets `@Default(true) bool switchGames`, like the Mac's other flags (`host_capabilities.dart:8-17`), mapped at `runtime_repository_impl.dart:33-42`. The host check ends before the shell shows (`router.dart:46`), so the side bar hides the item from its first frame, as Backends hides D3DMetal (`backends_page.dart:28`, `:48-49`).
- The second phase, not built now: Linux's host looks for AppImages (exec bit; FUSE), then a tar.gz or `PATH` binary the user picks, then Flatpak exports (exploration Q8); its whitelist adds `XDG_*` and `QT_*` and leaves out `APPIMAGE` (`platform_linux.dart:49`); a Flatpak runs as `flatpak run --file-forwarding <id> @@ <game> @@` and stops with `flatpak kill`.   `<game>` is the path `list` prints, as `bodega library` takes the key `bodega apps` prints (`:121-126`, `:185-190`).
  The verb grammar lives in `switch.dart`, beside the helpers: `switchVerb(args, out, [env])` gives the verb's work, a function of the data root that writes to `out` and gives the exit code, or null for a bad usage, which the CLI answers with its usage and 64 before `bodegaHome` runs. It takes one sink: no verb writes to stderr, since a verb's output, its notes included, is its result, as `bodega pads` prints its issues and `catalog install` its `note:` lines on stdout, and a failure goes through `main`'s catch. It finds all of it before it writes a line, so a failure, such as `CorruptData` from a `games.json` that does not parse, which the native apps' notes need, leaves no half status. `list` prints `title  titleId|-  path`, sorted by title. `add` takes each `.app` argument as an item, never a folder to scan, scans each other folder argument, a link to one included (§4), and prints each title it added, then how many were already listed. `open` prints `log: <log>`, waits with `exitOf` and exits with the game's code; it has no hints or anti-cheat watch, and `_follow` (`:259-285`) stays Wine's. Failures print `bodega: <message>` and exit 1 (i18n E6).
