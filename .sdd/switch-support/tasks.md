# Tasks · switch-support

**Conventions**
- Paths: `lib/`, `test/`, `macos/` and `tool/check_layers.sh` are in `apps/bodega/`, where the app's commands run; `engine/` is `packages/engine/`, where `dart` runs; other paths, `tool/version.sh` included, start at the repo root. `<tmp>`, the test Mac, the fixture, the native fixture, the game, `<stem>` and `build/bodega` are `specs/engine.md`'s; the fake Mac is `specs/app.md`'s; `<base>` is the commit of `main` the branch is taken from, `git merge-base origin/main HEAD`: cfd3e10, `v1.5.1`, onto which the branch moved from 7ef6006, i18n's docs on top of `v1.5.0` (SE1; in the lead's sandbox, the scratch tag `start` held `v1.5.0`'s code, the same as 7ef6006's). **(USER)**: only the user can do it: the push, or a check on a real Mac with their own Ryubing, keys, firmware and games, or a native app they made, recorded in `.sdd/switch-support/verify.md`; agents never start the emulator or a game (`.claude/CLAUDE.md:73`).
- Every task ends green. Its **Check** names what is new, on top of `dart analyze && dart test` in `engine/` and, from T14 on, `flutter analyze && flutter test && tool/check_layers.sh` in `apps/bodega`. From T2 until T14 the app does not analyze: `appErrorOf` (`apps/bodega/lib/data/service/repository_call.dart`, i18n E12) has no case yet for the five new failures, so M1 checks the engine alone. Run `flutter gen-l10n` after an ARB edit, and build_runner after a Freezed or Injectable one. Cases with mode-000 files skip as root; the real `plutil` and `xattr` cases run on the Mac only (`needs plutil`, `needs macOS`).
- i18n's conventions, as they stand when this change applies (`.sdd/i18n/design.md` §3–§6, §9): a failure is a final subclass of the sealed `EngineFailure` with an English message, which the CLI prints, and a case in `engine/test/english_test.dart`, and tests check it by type and fields (`throwsA(isA<SwitchGameNotFound>().having(…))`); `appErrorOf` maps it in one exhaustive switch, `domain/` carries the code and never a sentence, and `lib/app/shared/text/` words it, with a case in `test/app/text_test.dart`; all UI text comes from both ARBs through `context.l10n`, with its `@key` in `app_en.arb`, an `XTypeGroup` built and `context.l10n` read before an `await`; widget tests pump through `wrapApp` or `wrapRouter`, find English and reach Spanish only through `lookupAppL10n`. Everything in git is English (`.claude/CLAUDE.md:7`).
- Lines no task crosses (design §12; SN7): no link, URL, domain or forge path (owner/repo) of an emulator project, of nxnative, or of their downloads, keys, firmware or games, and no word on how to get them or how to make an app, in code, comments, tests, ARB descriptions, docs, scripts, commit messages or the pull request; legal documents may be cited. One exception, since T34: the emulator's official download page, whose URL only the `page` line of the emulator table in `switch.dart` and the tests hold, and which the app opens in the browser; of the emulator, text says only that it is missing, that Bodega opens that page, and that its app goes in Applications. Bodega only checks that those files exist: it never reads, decrypts or ships them, and copies the user's `.keys` files or hands their firmware to the emulator's own installer only at their pick (SN21, since 2026-11-12), and it never strips quarantine from an app it did not ship. Of a native app it reads only `DMTitleID`, `CFBundleExecutable` and its quarantine attribute, and it never builds one, runs nxnative's scripts or handles `prod.keys` for it. Tests use only the fixtures and empty files under `<tmp>`, never the real `/Applications` or `HOME` (SE23).
- The agent never commits or pushes. The user commits each milestone from a script the agent leaves beside the repo (SN15): each milestone is built in the agent's sandbox and brought into the branch's working tree, uncommitted, with codegen run there, so that the user can read the code and run the app; `../switch-commit.sh` commits T30's bump, M1, M2 and these docs, in four commits, and `../switch-m3.sh` commits M3. No patch file is involved. Each script stops if a check fails, runs `tool/version.sh check` before each code commit, pushes nothing, and has English messages with no link, no how-to and no AI attribution. The `bump-version` skill runs before every commit (`AGENTS.md:10`): `main` carries `1.5.1+13` and its last tag is `v1.5.1` (`1.5.0+12` and `v1.5.0` when the branch was taken), so `check` refuses M1's product changes, and T30's bump to `1.6.0+14` is the branch's first commit, of its `version:` line alone, which `../switch-commit.sh` makes before M1's, reading both `version:` lines rather than fixed numbers; the commits after it carry `1.6.0+14`, which the skill then leaves as it is (SN14).
