# Spec · Platform and rules

Requirements SN1..SN20: the host hooks (the `HostPlatform` getter, `MacEmulators` and its seams, the Linux stub, the capability, the emulator's environment), the rules and docs, the link guard, packaging, CI, the version and the delivery, and the USER checks on a real Mac (`design.md` §2, §5, §7, §11–§13). The engine part and the CLI are `engine.md` (SE); the app is `app.md` (SA). `lib/`, `test/` and `macos/` are under `apps/bodega/`, where the app's commands run; `engine/` is `packages/engine/`, where `dart test` runs; other paths start at the repo root. Line numbers are today's, with i18n's M1 committed (60e545a). `<tmp>` is a test's temporary folder; "Ryubing's row" is the one row of `switchEmulators` (SE2); "the fixture" is SE23's fake `<tmp>/Applications/Ryujinx.app`, version `1.3.3`; "the native fixture" is SE23's fake native app `<tmp>/apps/Bodega Test.app`; "the test Mac" is SE23's. `<base>` is the commit of `main` the branch is taken from, as in SE1: `git merge-base origin/main HEAD`, cfd3e10, `v1.5.1`, onto which the branch moved from 7ef6006, i18n's docs on top of `v1.5.0` (in the lead's sandbox, the scratch tag `start` held `v1.5.0`'s code, the same as 7ef6006's). `build/bodega` is the CLI that `dart compile exe bin/bodega.dart -o ../../build/bodega` builds in `engine/`. **(USER)**: only the user can check it, on a real Mac with their own Ryubing, keys, firmware and games, or a native app they made; the results go in `.sdd/switch-support/verify.md`, beside SE24's (the CLI) and SA22's (the page).

## SN1 · The emulator host
`HostPlatform` (`engine/lib/platform.dart:19-78`) shall gain one abstract getter beside `gamepads()` (`:48-50`), `EmulatorHost get emulators`, answered by `MacPlatform` with `const MacEmulators()` and by `LinuxPlatform` with `const LinuxEmulators()`, one line each. `EmulatorHost` (`supported`, `find(emulator, env, {picked})`, `confirm(emulator, path)`, `nativeApp(app)`, `files(emulator)`, `env(parent)`, `runs(pid, exe)`, `stop(pid, exe, {kill})`) and both classes live in `engine/lib/switch.dart`, and a host reads only its own sub-record of a row (design §7). The Mac's `nativeApp` reads a native app's `DMTitleID` and `CFBundleExecutable` through `plistKey` and its attribute through `quarantine` (SE6, SE7); its `runs` asks `/bin/ps -ww -p <pid> -o command=` (in `/bin`, not `MacPlatform.tool`'s `/usr/bin`, `platform_mac.dart:108-109`; `-ww` as SE18 says), and its `stop` sends SIGTERM, or SIGKILL when `kill`, through Dart's own `Process.killPid`, only while the pid runs `exe`, with no `kill` tool. `LinuxEmulators` is the "not yet" stub.
- **Given** `hostPlatform = const TestMac()` (`engine/test/_mac.dart:8`), which does not override the getter, **then** `hostPlatform.emulators` is a `MacEmulators` whose `supported` is true; **given** `const LinuxPlatform(mangoHud: false)`, **then** it is a `LinuxEmulators` whose `supported` is false.
- **Given** `const LinuxEmulators()` and Ryubing's row, **when** `find(row, {'HOME': '/home/q'})` runs, **then** it completes with null; **when** `confirm(row, '/home/q/Ryujinx.app')`, `nativeApp('/home/q/Game.app')`, `files(row)`, `env({'HOME': '/home/q'})`, `runs(999999, '/bin/sleep')` and `stop(999999, '/bin/sleep')` run, **then** each throws `NotAvailable` with `what == 'switch'` and `host == 'Linux'`: at once for `files` and `env`, as a failed future for the others.

These cases run on Linux CI too.
- **Given** `MacEmulators(root: <tmp>)`, **when** `files(row)` is read, **then** it is the row's `mac.files`: data `<bin>/portable`, `<dir>/portable`, `~/Library/Application Support/Ryujinx`; keys `<data>/system/prod.keys`; `userKeys` `~/.switch/prod.keys`; firmware `<data>/bis/system/Contents/registered`; and the row's `linux` is null.

## SN4 · The emulator's environment
`EmulatorHost.env(parent)` shall be the whole environment of an emulator, which the launch passes with `includeParentEnvironment: false`, as `_start` passes Wine's (`engine.dart:453`; SE14). On the Mac it holds `HOME`, `USER`, `LOGNAME`, `TMPDIR` and `__CF_USER_TEXT_ENCODING`, each only when `parent` has it, and `PATH=/usr/bin:/bin:/usr/sbin:/sbin`: the session part of `baseEnv` (`platform_mac.dart:79-87`) without its Wine and .NET keys (`:88-91`), because Ryubing is a .NET program and `DOTNET_EnableWriteXorExecute=0` must not reach it. A native app gets the same environment and nothing more, no `DM_` variable among it, so its own settings window and the user's saved choices apply (design §5). On Linux it throws `NotAvailable` (SN1); the Linux list, with `XDG_*` and `QT_*` and without `APPIMAGE` (`platform_linux.dart:49`), is the second phase's (design §7).
- **Given** a parent with the five session keys of "wineEnv is hermetic" (`engine_test.dart:94`) and `PATH=/opt/homebrew/bin`, `LANG=es_ES.UTF-8`, `WINEPREFIX=/b/p`, `WINEDEBUG=+all`, `WINEMSYNC=1`, `ROSETTA_ADVERTISE_AVX=1`, `MVK_CONFIG_LOG_LEVEL=2`, `DOTNET_EnableWriteXorExecute=0`, `DOTNET_ROOT=/usr/local/share/dotnet`, `DYLD_LIBRARY_PATH=/opt/homebrew/lib`, `BODEGA_HOME=/b`, `DM_LAUNCHER=0` and `DM_FPS_TARGET=30`, **when** `MacEmulators(root: <tmp>).env(parent)` runs, **then** it equals `{HOME: /Users/q, USER: q, LOGNAME: q, TMPDIR: /var/folders/x/T/, __CF_USER_TEXT_ENCODING: 0x1F5:0x0:0x8, PATH: /usr/bin:/bin:/usr/sbin:/sbin}`; with only `{HOME: /Users/q}`, it equals `{HOME: /Users/q, PATH: /usr/bin:/bin:/usr/sbin:/sbin}`.
- **Given** the test Mac and that parent with `HOME=<tmp>/home`, **when** `openSwitchGame` runs a listed game, **then** the fixture's recorded environment, without the shell's own `PWD`, `SHLVL`, `_` and `OLDPWD`, equals `env(parent)`, and so does the native fixture's when it runs (SE14 checks the launch's side).
- **Given** the change, **then** "wineEnv is hermetic" passes as it is: Wine keeps `DOTNET_EnableWriteXorExecute=0` and its other keys.
- **Check:** `dart test test/switch_test.dart test/engine_test.dart` in `engine/`.

## SN5 · The Mac code runs on Linux CI
`MacEmulators({String root = '', plistKey, quarantine})` shall take three seams: `root` prefixes `/Applications`, `plistKey` replaces `/usr/bin/plutil -extract <key> raw <plist>`, and `quarantine` replaces `/usr/bin/xattr -p com.apple.quarantine <app>`, the last two for the emulator and for native apps alike; `const MacEmulators()` uses `/Applications` and the two tools, and a failed `plutil` means "not this candidate", never an error (design §2). With the seams, every Switch case runs on Linux CI against the fixture (SE23); the real tools run on the Mac only, skipped elsewhere as `needs plutil` where `/usr/bin/plutil` is missing (as `backends_test.dart:423` skips) and as `needs macOS` for the real `xattr` case (SE7), since Linux's `xattr` differs; and no test sees the real `/Applications` or the real `HOME`.
- **Given** `MacEmulators(root: '<tmp>', plistKey: <a regex over the fixture's XML>, quarantine: <a set of paths>)`, an env with `HOME=<tmp>/home` and the fixture, **when** `find(row, env)` runs on Linux CI, **then** it returns `(app: '<tmp>/Applications/Ryujinx.app', exe: '<tmp>/Applications/Ryujinx.app/Contents/MacOS/Ryujinx', version: '1.3.3', picked: false, quarantined: false)`, and `quarantined` turns true once the set holds the app; with a `plistKey` that fails for every key, it returns null, and so does `nativeApp` of the native fixture, which otherwise gives `titleId` `0100F00DBA5E0000` (SE6).
- **Given** `MacEmulators(root: '<tmp>')` on a Mac, with no `plistKey` or `quarantine`, **when** it finds the fixture, **then** `/usr/bin/plutil` reads `1.3.3`; on Linux the case shows as skipped, `needs plutil`.
- **Given** the test Mac with no fixture, **when** `checkSwitch(home, env)` runs, **then** `install` is null and `keys` and `firmware` are false, also on a Mac whose real `/Applications` holds `Ryujinx.app` and whose real `~/Library/Application Support/Ryujinx` holds keys and firmware: nothing outside `<tmp>` is looked at.
- **Check:** `dart test test/switch_test.dart` in `engine/`, on the Mac (every case runs) and in CI (the Mac-only ones skipped); SE23's greps.
