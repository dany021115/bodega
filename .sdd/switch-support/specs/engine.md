# Spec · Engine and CLI

Requirements SE1..SE24: the engine's Switch part, `engine/lib/switch.dart`, and the `bodega switch` verbs, for game files, which open with Ryubing, and for native apps, the Mac apps users make of their own games with nxnative (`design.md` §1–§8, §11, §13). `engine/` is `packages/engine/`, where `dart test` and `dart run bin/bodega.dart` run; other paths start at the repo root, and bare Dart file names are unique in the repo. Line numbers are today's, with i18n's M1 committed (60e545a). This part is applied after i18n's M2, so failures, the English CLI and "the engine grep" are as `.sdd/i18n/design.md` §4 and `.sdd/i18n/specs/engine-codes.md` (E1–E8) make them. The host hooks themselves (the `HostPlatform` getter, the Linux stub, the capability, the whitelist's own test), the link guard, rules, docs, delivery and most USER checks are `platform-and-rules.md` (SN); the app is `app.md` (SA).

**The test Mac** (SE23) is `useMac()` with `hostPlatform` a `TestMac` whose `emulators` is `MacEmulators(root: <tmp>, …)`, `<tmp>` being the test's temporary folder; `home` is the data root `<tmp>/bodega`, and `env` an env map whose `HOME` is `<tmp>/home`. **The fixture** is the fake `<tmp>/Applications/Ryujinx.app`, version `1.3.3`, whose script writes what it got under `$HOME`; **the game** is the empty file `<tmp>/games/Bodega Test [0100F00DBA5E0000][v0] (EU).nsp`; **the native fixture** is the fake native app `<tmp>/apps/Bodega Test.app` (SE6), whose `Info.plist` has `DMTitleID` `0100F00DBA5E0000` and `CFBundleExecutable` `nxnative` and whose `Contents/MacOS/nxnative` is a copy of the fixture's script (SE23); `<stem>` is a run's log path without `.log`; `build/bodega` is the CLI built by `dart compile exe bin/bodega.dart -o ../../build/bodega` in `engine/`. Cases with mode-000 files show that nothing is read, and are skipped when the tests run as root. **(USER)**: only the user can check it, on a real Mac with their own Ryubing, keys, firmware and game, or a native app they made; agents never start the emulator or a game (`.claude/CLAUDE.md:73`).

## SE1 · One engine part, Wine untouched
The engine shall hold Switch in one new part, `engine/lib/switch.dart`, behind one more `part` line (`engine.dart:14-21`): the emulator table, the store, the settings, the status, the scan, the native apps' checks, the launch, the CLI's verb grammar and helpers (SE21), the five failures (SE20) and the emulator hosts (design §1, §7). Wine's `_launch`, `_start`, `_newLog`, `exitOf`, `apps.json` and `InstalledApp` shall stay as they are, so removing Switch is deleting that file and the few lines that name its types.
- **Given** `<base>`, the commit of `main` the branch is taken from (`git merge-base origin/main HEAD`): cfd3e10, `v1.5.1`, onto which the branch moved from 7ef6006, the user's commit of i18n's docs on top of `v1.5.0` (7ba0a73, its parent, with the same code; in the lead's sandbox, the scratch tag `start` held that code), **when** `git diff <base> -- packages/engine/lib/engine.dart` runs, **then** it adds one line, `part 'switch.dart';`, and changes nothing else; `git diff --stat <base> -- packages/engine` lists only `bin/bodega.dart`, `lib/engine.dart`, `lib/platform.dart`, `lib/platform_linux.dart`, `lib/platform_mac.dart`, `lib/switch.dart`, `test/english_test.dart`, `test/switch_links_test.dart` and `test/switch_test.dart`.
- **Given** the change, **when** `grep -rlE 'Switch|Emulator|switchGames|switch\.dart' packages/engine/lib` runs, **then** it lists only the five `lib/` files of that list (today it lists nothing).
- **Check:** those two commands.

## SE2 · The emulator table
`switch.dart` shall describe emulators as data (design §1): the records `Emulator(id, name, page, extensions, args, mac?, linux?)`, `EmulatorArgs(headless, fullscreen, game)`, `EmulatorOnMac(bundleId, app, executable, files)`, `EmulatorOnLinux(appImages, flatpak?, commands, files)` and `EmulatorFiles(data, keys, userKeys?, firmware)`, in which `~` is `HOME`, `<bin>` the executable's folder, `<dir>` the folder that holds the app, `<data>` the data folder in use, and the last `data` entry the default one; and `const switchEmulators`, with one row, Ryubing, whose comment names its sources at Ryubing commit `a61a426` (MIT) by file, as `catalog_data.dart:1-3` names its own, never by link. `page` is the emulator's official download page, the one link the repo holds of an emulator, in this row alone (SN7, SN10; the user's decision of 2026-11-11, proposal.md): the CLI's status names it (SE21) and the app opens it in the browser while no install is found (`app.md` SA14), as D3DMetal's section opens `gptkReleases`' page (`backends.dart`, I1); Bodega never downloads, bundles or installs the emulator. A host reads only its own sub-record, so Eden or Linux arrive as a row or a sub-record, not as new logic.
- **Given** `switchEmulators`, **when** the test reads it, **then** it holds one row: `id` `ryubing`, `name` `Ryubing`, `page` Ryubing's official download page (its URL is in the row and the tests only, never in this spec), `extensions` `[xci, nsp, pfs0, nca, nro, nso]`; `args` headless `[--no-gui, --use-main-config]`, fullscreen `[--fullscreen]`, game `[{game}]`; `mac` `org.ryujinx.Ryujinx`, `Ryujinx.app`, `Ryujinx`, with `data` `[<bin>/portable, <dir>/portable, ~/Library/Application Support/Ryujinx]`, `keys` `<data>/system/prod.keys`, `userKeys` `~/.switch/prod.keys` and `firmware` `<data>/bis/system/Contents/registered`; `linux` null.
- **Given** the table's comment, **then** it names `a61a426`, `MIT` and the files of design §1's table (`ApplicationLibrary.cs`, `CommandLineState.cs`, `Options.cs`, `Info.plist`, `create_app_bundle.sh`, `AppDataManager.cs`, `VirtualFileSystem.cs`, `ContentManager.cs`, `ContentPath.cs`), and holds no `://` or `www.`: the row's `page` line is the only line of `switch.dart` that does (SN10).
- **Check:** `dart test test/switch_test.dart` in `engine/` (the row, field by field); `grep -n 'a61a426' packages/engine/lib/switch.dart`; `grep -nE '://|www\.' packages/engine/lib/switch.dart` prints one line, the row's `page`; the link guard, `engine/test/switch_links_test.dart` (SN10).

## SE3 · Data under `switch/`, made on demand
The engine shall keep Switch's data in `$BODEGA_HOME/switch/`, made by the first write and never by `bodegaHome` (`engine.dart:33-35`): `games.json` as `{"games": [{"path", "title", "titleId"?, "added"}]}`, with `titleId` only when known and `added` an ISO UTC date as `installedAt` is (`apps.dart:124`); `settings.json` (SE4); and `logs/` (SE15). Every JSON write shall go through `_writeJson` (`backends.dart:512-517`), atomic, and a file that does not parse or has the wrong shape shall throw `CorruptData` with that file as `source` (`.sdd/i18n/design.md` §4) and stay as it was. A rewrite of `games.json` keeps each entry as it was read, keys the engine does not know included; one of `settings.json` holds its three known keys only, as `_saveSettings` writes (SE4).

## SE6 · What confirms an app, and the pick
An app shall be confirmed only when its `Contents/Info.plist` has `CFBundleIdentifier` equal to the row's `bundleId` and `CFBundleExecutable` equal to its `executable` (Eden reuses old yuzu's id, so the id alone tells nothing), and `Contents/MacOS/<executable>` is a regular file with an exec bit, the test `_onPath` makes (`platform_linux.dart:290-299`). Each key shall be one `/usr/bin/plutil -extract <key> raw <plist>`, as `d3dmetalVersion` reads one (`backends.dart:95-107`), whose failure or empty value means "not this candidate", never an error; `CFBundleShortVersionString` gives the version, or null. `chooseEmulator(home, app)` shall save a confirmed `app` as the pick, absolute and without a trailing `/` (SE10's rule), throw `NotAnEmulator(app, 'Ryubing')` and save nothing otherwise, and forget the pick for null, the CLI's `auto`. A native app (design §4) shall be a `.app` whose `Contents/Info.plist` has `DMTitleID`, read with one `plutil -extract DMTitleID raw` through the same seam, whose failure or empty value means "not a native app", never an error: nothing else makes one or refuses one. The host's `nativeApp(app)` (SN1) shall give null without it, else `NativeApp(titleId, exe, quarantined)`: `exe` is `Contents/MacOS/<CFBundleExecutable>`, read the same way and held to the same regular file with an exec bit in `Contents/MacOS/`, or null, which only a launch minds (SE14): a `CFBundleExecutable` that holds a `/` gives null, even one that comes back there, such as `../MacOS/nxnative`; `quarantined` is SE7's.
- **Given** the fixture with `CFBundleIdentifier` `com.yuzu-emu.yuzu`, or with `CFBundleExecutable` `eden`, or with `Contents/MacOS/Ryujinx` at mode 644, or with no `Info.plist`, or `<tmp>/nope.app`, **when** `chooseEmulator(home, <it>)` runs, **then** it throws `NotAnEmulator` with that `path` and `name` `Ryubing`, and `settings.json` is unchanged; any of the four broken fixtures, as the only copy in `<tmp>/Applications`, gives `install == null`.
- **Given** the fixture without `CFBundleShortVersionString`, **then** it is confirmed, with `version == null`; **given** `<tmp>/picked/Ryujinx.app/`, **then** the pick is saved as `<tmp>/picked/Ryujinx.app`.
- **Given** the native fixture, **when** `nativeApp('<tmp>/apps/Bodega Test.app')` runs on the test Mac, **then** it gives `(titleId: 0100F00DBA5E0000, exe: <tmp>/apps/Bodega Test.app/Contents/MacOS/nxnative, quarantined: false)`; with an `Info.plist` that lacks `DMTitleID`, or with none, it gives null; with no `CFBundleExecutable`, with `CFBundleExecutable` `../MacOS/nxnative`, or with `Contents/MacOS/nxnative` at mode 644, `exe` is null.
- **Given** a Mac, **when** `MacEmulators(root: <tmp>)` confirms the fixture with the real `plutil`, **then** its version is `1.3.3`, and its `nativeApp` of the native fixture gives `titleId` `0100F00DBA5E0000`; the cases are skipped where `/usr/bin/plutil` is missing, as `backends_test.dart:423` skips.

## SE7 · Quarantine reported, never stripped
`EmulatorInstall.quarantined` shall be true when `/usr/bin/xattr -p com.apple.quarantine <app>` exits 0, and the engine shall never remove that attribute from an emulator or from anything inside it: `afterExtract` and `_stripQuarantine` (`platform_mac.dart:114-117`, `:275-282`) stay for Bodega's own copies. The attribute stays after the user approves the app once, so it means "maybe blocked", and the words around it are conditional (SE21; `app.md`). A native app's attribute shall be read the same way, as `NativeApp.quarantined` (SE6), shown as the emulator's is (SE21; `app.md`), and never removed: nxnative signs its apps ad hoc unless they were packed with another identity, and never notarizes them (design §4). No test shall exec a bundle that carries the attribute: macOS then holds the new process behind a Gatekeeper prompt that only the user can answer, as happened in M1, so what a quarantined launch does is SN19's and SN20's (USER).
- **Given** the test Mac whose `quarantine` seam holds `<tmp>/Applications/Ryujinx.app`, **when** `checkSwitch` runs, **then** `install.quarantined` is true; for a copy the seam does not hold, false; with the native fixture in the seam, `nativeApp` gives `quarantined: true`.
- **Given** a Mac and the fixture marked with the real `xattr -w com.apple.quarantine '0081;00000000;Test;' <tmp>/Applications/Ryujinx.app`, **when** `checkSwitch` runs over `MacEmulators(root: <tmp>)` with the real tools, **then** `install.quarantined` is true; **when** `openSwitchGame` then runs with `HOME=<tmp>/nope`, **then** it stops right before the exec with `ProcessFailed` (SE16), and `xattr -p com.apple.quarantine` on the fixture still exits 0 with the same value; the native fixture, marked the same way, is reported quarantined by `nativeApp`, and keeps its value after `openSwitchGame` stops the same way. The cases are skipped off macOS, since Linux's `xattr` differs (SN5).
- **Check:** `dart test test/switch_test.dart`; `grep -n xattr packages/engine/lib/switch.dart` prints only the `-p` call.

## SE8 · The status checks existence only

## SE10 · Adding game files
`addSwitchGames(home, paths, {emulators})` shall take each path absolute: a relative one against the current folder, with `.` and `..` worked out from the text alone, no trailing `/` and links kept, the rule every Switch function applies to the paths it takes. A path whose name ends in `.app`, without case, is a native app's (design §4): it shall throw `NotAvailable` where its host is not supported (SE9), `MissingFile(path)` when nothing is there, and `NotASwitchGame(path, extensions)` when the host's `nativeApp` gives null (SE6). Any other path's extension shall be one of the row's, compared without case, and then the path a file: it throws `NotASwitchGame(path, extensions)` for another extension, or for a path that holds something other than a file, such as a folder named `x.nsp`, and `MissingFile(path)` only when nothing is there, as for a `.app`. All of it comes before it writes anything, and it writes `games.json` only when a path is new; it returns `(added, known)`, where `known` counts paths already listed or given twice. It shall read nothing from the files and copy none, nor anything of a native app but what `nativeApp` reads, and it takes a `.nca` picked by hand.
- **Given** the game at mode 000 and an empty `<tmp>/games/OTHER.XCI`, **when** `addSwitchGames(home, [<the game>, '<tmp>/games/OTHER.XCI'])` runs, **then** it returns `(added: 2, known: 0)`; **when** it runs with the game and `<tmp>/games/x/../Bodega Test [0100F00DBA5E0000][v0] (EU).nsp`, **then** it returns `(added: 0, known: 2)`, and the list still holds two games.

## SE11 · Scanning a folder once
`addSwitchFolder(home, folder, {emulators})` shall add, as SE10 does, the files whose extension is one of the row's except `nca` (an unpacked title holds many content archives, each a part, not a game), found by name in `folder` and the two levels below it, following no link and passing over hidden entries and the folders it may not list. Each `*.app` folder it meets (without case) it shall check as SE10 does, add when the host finds a native app and pass over otherwise, and never list: a scan never goes inside an app, and a `folder` that is itself an app is one it meets, added when the host finds a native app, passed over otherwise and where the host is not supported, and never listed inside. Where the host is not supported, it passes over every `*.app`, as before, and throws nothing for them. `folder` itself is followed when it is a link, and nothing inside it is, so the games of a link to a folder are stored under the link's path. It shall keep no folder, so nothing is ever re-scanned and no `hidden` list is needed (design §4). It shall throw `MissingFile(folder)` for a path where no folder is, nothing or something else such as a file, and give `(added: 0, known: 0)` for a `folder` it may not list, as it passes over the folders below it that it may not list: a folder macOS denies Bodega looks empty, with no error (SN19 sees what a real Mac shows).
- **Given** under `<tmp>/lib`: `a.nsp` at mode 000, `x/b.XCI`, `x/y/c.nro`, `x/y/z/d.nsp`, `x/e.nca`, `.h/f.nsp`, `.g.nsp`, `Tool.app/g.nsp` with no `Info.plist`, `Game.app`, a copy of the native fixture that also holds an empty `h.nsp`, `readme.txt`, a link `l.nsp` to `<tmp>/elsewhere/l.nsp`, a link `ld` to `<tmp>/elsewhere/`, which holds `m.nsp`, and `locked/k.nsp` in a folder `locked/` then set to mode 000, **when** `addSwitchFolder(home, '<tmp>/lib')` runs on the test Mac, **then** it returns `(added: 4, known: 0)` and the list holds `a.nsp`, `x/b.XCI`, `x/y/c.nro` and `Game.app`, but not `Game.app/h.nsp` nor anything of `Tool.app`; a second run returns `(added: 0, known: 4)`; with `hostPlatform` a Linux host, a first run returns `(added: 3, known: 0)`, passing over both apps.
