# Spec · App

Requirements SA1..SA22: the Flutter app's side of Switch support (`design.md` §6, §9–§11, §13). `lib/` and `test/` are `apps/bodega/lib/` and `apps/bodega/test/`, where the app's commands run; `engine/` is `packages/engine/`, where `dart test` runs; other paths start at the repo root. Bare Dart file names are unique in the repo. Line numbers are today's, with i18n's M1 committed (60e545a). This part is applied once i18n's T26 and T27 are in (design §13), so for what i18n's M2 writes first (`app_error.dart`, `repository_call.dart`, `shell_body.dart`, new `error_text.dart`) it cites i18n's design and specs ("i18n E10", "i18n L8"). `<base>` is the commit of `main` this change's branch is taken from, cfd3e10, `v1.5.1` (SE1). The engine and the CLI are `engine.md` (SE); the host hooks, the link guard, rules, docs, delivery and the engine's USER checks are `platform-and-rules.md` (SN). **(USER)**: only the user can check it, on a real Mac with their own Ryubing, keys, firmware and game, or a native app they made.

**Fixtures.** Games, ids and logs are made up: `/g/Bodega Test [0100F00DBA5E0000][v0] (EU).nsp`, titled `Bodega Test` with the id `0100F00DBA5E0000`; `/g/Homebrew Demo.nro`, with no id; `/g/Bodega Test.app`, a native app (design §4) titled `Bodega Test`, with no id; the log `/l/a.log`. **The fake Mac** of `test/data/switch_repository_test.dart` (new) is `engine.hostPlatform`, set for each test and restored after it, as a Mac whose `emulators` work over a temporary folder `<tmp>` (design §2, §11): `MacEmulators(root: <tmp>, plistKey: …, quarantine: …)`, `plistKey` a regex over the fixture's XML and `quarantine` a set of paths, with the repository's `environment` (SA4) set to `{'HOME': '<tmp>/home'}`, a folder the test makes, so `HOME` is `<tmp>/home` for finding the app, for the data folders and as a launch's folder, and a Ryubing or a data folder of the machine that runs the test is never found, read or started. Its `<tmp>/Applications/Ryujinx.app` has an `Info.plist` that says `org.ryujinx.Ryujinx`, `Ryujinx` and `1.3.3`, and a `Contents/MacOS/Ryujinx` script that writes nothing, waits while a `hang` file beside it exists, and exits with the code in a `code` file beside it, or 0. Its native app, `<tmp>/apps/Bodega Test.app`, has an `Info.plist` that says `DMTitleID` `0100F00DBA5E0000` and `CFBundleExecutable` `nxnative`, and that same script as `Contents/MacOS/nxnative`. So `hang` and `code` sit inside the bundle, in `Contents/MacOS/`, while the engine's fixture keeps them under its `$HOME` (SE23). macOS checks a new program while it starts, and a bundle whose files vanish meanwhile makes Gatekeeper prompt on the user's screen (design §11), so a test makes `hang` before any run and deletes it only after that run has ended, and a `tearDown`, which runs before `<tmp>` is deleted, deletes any `hang` under `<tmp>`, waits up to 10 s for no process whose command line names `<tmp>`, then sends SIGKILL to any left. The data root is `<home>`, `<tmp>/bodega`, through `TestHome` (`test/data/_home.dart`). It runs on Linux CI too. No real emulator, keys, firmware, game or native app is in git or downloaded.

## SA1 · Five `AppError` codes, mapped in one switch
`AppError` (i18n design §5) shall gain `noEmulator(name, app)`, `notAnEmulator(path, name)`, `notASwitchGame(path)`, `switchGameNotFound(path)` and `switchGameRunning(path)`, each with `{String? detail}`, so the union holds 36 codes, and `appErrorOf` shall map the five Switch failures of design §6 in five new cases with `detail: failure.message` and still no default branch, each to the code of its name. `NotASwitchGame` is new in M1, so it maps to `notASwitchGame` directly: "Add games" takes any app bundle (SA16), so one that is not a native app reaches it from the app, and its extensions stay in `detail` (design §6). `MissingFile`, `CorruptData`, `NotAvailable` and `ProcessFailed` keep i18n's mappings: `badPath(PathProblem.missing(path))`, `corruptData`, `unknown` and `processFailed` (i18n E10).
- **Given** a call that throws `NoEmulator('Ryubing', 'Ryujinx.app')`, **when** `repositoryCall` wraps it, **then** it returns `Left(AppError.noEmulator('Ryubing', 'Ryujinx.app', detail: <its message>))`; `NotAnEmulator('/Applications/Other.app', 'Ryubing')`, `SwitchGameNotFound('/g/a.nsp')` and `SwitchGameRunning('/g/a.nsp')` give the codes of their names with those fields, and `NotASwitchGame('/Applications/Other.app', ['xci', 'nsp', …])` gives `notASwitchGame('/Applications/Other.app')` with its message as `detail`.
- **Given** `MissingFile('/g/gone.nsp')` and `NotAvailable('switch', 'Linux')`, **when** wrapped, **then** they give `badPath(PathProblem.missing('/g/gone.nsp'))` and `unknown`, as Wine's failures do.
- **Given** a scratch copy with one of the five cases deleted, **when** `flutter analyze` runs, **then** it reports `appErrorOf`'s switch as not exhaustive (i18n E12).
- **Check:** `flutter test test/data/repository_call_test.dart`; `flutter analyze` on the scratch copy; i18n E10's grep (`grep -rnE '_ =>|default:' lib/data`) still prints only the switch on the OS in `update_repository_impl.dart`.

## SA4 · The repository: status and games
`SwitchRepository` (`lib/domain/repository/switch_repository.dart`) shall have `status()`, `games()`, `addFiles(paths)`, `addFolder(folder)`, `remove(path)`, `chooseEmulator(app)`, `setFullscreen(value)`, `open(path)` and `stop(path)`, each a `Future<Either<AppError, T>>` through `repositoryCall` (`architecture.md:37`), and `running()` and `waitRun(log)`, which never fail (SA7). `SwitchRepositoryImpl` (`lib/data/repository/switch_repository_impl.dart`) shall be `@LazySingleton(as: SwitchRepository)` over `EngineHome`, import the engine `as engine` (`architecture.md:26`) and run `games()`, `addFiles` and `addFolder` in `Isolate.run` (design §4). It keeps `@visibleForTesting Map<String, String> environment = Platform.environment`, as `UpdateRepositoryImpl` does (`update_repository_impl.dart:50-51`), and passes it as `env` to `checkSwitch` and `openSwitchGame`, the two calls that read `HOME`. `status()` joins `checkSwitch` and the saved settings, with the row's app file name (`mac.app`) as `appName` and its `page`; `games()` sorts by title ignoring case (`apps.dart:244-246`) and sets `native` from the engine's rule (a `.app`, design §4) and `quarantined`, for a native game on a supported host, from the host's `nativeApp` (design §7). It reads `engine.hostPlatform.emulators` before `Isolate.run` and passes it in for `games()`, `addFiles` and `addFolder`, since the isolate's globals start fresh (SA5 shows that the adds pass it).
- **Given** the fake Mac, an empty `<tmp>/home/Library/Application Support/Ryujinx/system/prod.keys` and an empty `…/Ryujinx/bis/system/Contents/registered/`, **when** `status()` runs, **then** it returns `SwitchStatus(emulator: 'Ryubing', appName: 'Ryujinx.app', page: <the row's page>, install: EmulatorInstall(app: '<tmp>/Applications/Ryujinx.app', version: '1.3.3', picked: false, quarantined: false), keys: true, firmware: false, fullscreen: true, extensions: ['xci', 'nsp', 'pfs0', 'nca', 'nro', 'nso'])`; with one file in `registered/`, `firmware: true`; with the app's path in the `quarantine` set, `quarantined: true`; with no app, `install: null`.
- **Given** games added from `<tmp>/g/beta.nsp`, `<tmp>/g/Alpha.xci` and `<tmp>/g/gamma.nro`, **when** `games()` runs, **then** their titles come as `Alpha`, `beta`, `gamma`.
- **Given** the native app added, **when** `games()` runs, **then** it lists it with `native: true` and `quarantined: false`, and the game files with `native: false`; with its path in the `quarantine` set, `quarantined: true`.
- **Given** a `<home>/switch/games.json` that does not parse, **then** `games()` returns `Left(AppError.corruptData(…))`; **given** `engine.hostPlatform` a Linux host, **then** `status()` returns `Left(AppError.unknown(…))`, from `NotAvailable`.
- **Check:** `flutter test test/data/switch_repository_test.dart`; `grep -c 'Isolate.run' lib/data/repository/switch_repository_impl.dart` prints 3; `grep -nE 'readAs|openRead|\.open(Sync)?\(|lengthSync|statSync' lib/data/repository/switch_repository_impl.dart` prints nothing.

## SA9 · `SwitchBloc`: state and load
`SwitchBloc` (`lib/app/bloc/switch/`) shall be a `@lazySingleton` provided in `main.dart` (`:50-62`), as `LibraryBloc` is, because a running game outlives its page (`architecture.md:31`). Its `sealed` events are `load`, `addFiles`, `addFolder`, `remove`, `chooseEmulator`, `setFullscreen`, `open`, `stop` and `ended(path, code)`; its state holds `isLoading` (true until the first load ends), `isAdding`, `status`, `games`, `running` (game path → log), `notice`, a `SwitchNotice` union (`added(added, known)` or `exited(title, code)`), with `noticeId` (as `toast` and `toastId`, `library_state.dart:13-15`), and `error`. `load` shall read the status, the games and `running()`, and follow each run it does not follow yet. A read that fails keeps the last status and games and sets `error`, the status's error when both fail, as `GamepadsBloc` keeps its last report and `LibraryBloc` its apps: so `status` is null only until a read succeeds.
- **Given** a repository whose `status()` gives S, `games()` gives `[Bodega Test, Homebrew Demo]` and `running()` gives `[SwitchRun(game: <Bodega Test's path>, log: '/l/a.log')]`, **when** `load` is added, **then** the state has `isLoading: false`, `status: S`, those games and `running: {<that path>: '/l/a.log'}`, and `waitRun('/l/a.log')` is called once; a second `load` calls it no more.
- **Given** `status()` failing with `unknown` while `games()` succeeds, on a first load, **then** `games` is set, `status` stays null and `error` is that code.
- **Given** a state with a status and games, **when** a later `load` gets a `Left` from `status()` and from `games()`, **then** the status and the games stay as they were and `error` is `status()`'s code.
- **Check:** `flutter test test/app/switch_bloc_test.dart` (new), with `bloc_test` and a mocked `SwitchRepository` (`code-style.md:24`); `grep -n 'getIt<SwitchBloc>' lib/main.dart` prints one provider line.

## SA10 · `SwitchBloc`: the list and the settings

One add runs at a time: an `addFiles` or `addFolder` that comes while `isAdding` is ignored, since each add reads and rewrites `games.json` in its own isolate, and two at once could lose an entry.

- **Given** `chooseEmulator('/x/Ryujinx.app')` answered `Left(notAnEmulator('/x/Ryujinx.app', 'Ryubing'))`, **then** `error` is that code and `status` is unchanged; answered with a `Right`, `status()` is called again.
- **Given** `setFullscreen(false)` answered with a `Right`, **then** `status.fullscreen` is false; **given** `remove(<path>)`, **then** `games()` is called again and `running` is unchanged.
- **Check:** `flutter test test/app/switch_bloc_test.dart`.

## SA11 · `SwitchBloc`: running games
`open` shall launch a game, put its log in `running` and follow it, ignoring a second `open` of the same game within 2 s (`library_bloc.dart:41-45`); a follow shall await `waitRun` and add `ended(path, code)` unless the bloc is closed (`:169-173`); `ended` shall drop the run and set `exited(title, code)` for a code outside the normal set of the game's kind, unless a Stop from Bodega caused it: `{0}` for a native game, nxnative's quit (design §4), whose 70 and 134 take the usual notice; `{0}` for a game file until SA22's exit codes say what a closed window gives; a game the list no longer holds counts as a game file. A null code (a failed wait) sets nothing. `exited` names the game's title, or its file name when the list no longer holds it; `stop` calls the repository. A run's end counts as caused by a Stop from Bodega like this: the bloc marks the path before it calls `stop`, since the engine waits up to 5 s for the run to end before it returns and the end may reach the bloc first; a `Left` unmarks it; a `Right` that finds no run of that path in `running` drops the mark, so a Stop of a game that does not run here hides no later code; and the run's end takes the mark.
- **Given** `open(P)` answered `/l/a.log`, **then** `running` is `{P: '/l/a.log'}` and `waitRun('/l/a.log')` is called; two `open(P)` in a row call `repository.open(P)` once, while an `open(Q)` between them still opens Q.
- **Given** that run, **when** `waitRun` gives 1, **then** P leaves `running` and `notice` is `exited('Bodega Test', 1)`; when it gives 0 or null, there is no notice; a run of `/g/x.nsp`, which the list does not hold, ending with 1 gives `exited('x.nsp', 1)`; a run of the native `Bodega Test` ending with 134 gives `exited('Bodega Test', 134)`, and with 0 no notice.
- **Given** `stop(P)` and then `waitRun` giving 143, **then** there is no notice, whether the run's end comes before the Stop's `Right` or after it, and P's next run ending with 1 sets `exited`; after a `stop(P)` answered with a `Left`, a later 1 still sets `exited`; a `stop(P)` answered with a `Right` while P is not in `running` leaves no mark, so P's next run ending with 1 sets `exited`.
- **Given** the bloc closed before `waitRun` completes, **then** it adds no event.
- **Check:** `flutter test test/app/switch_bloc_test.dart`.

## SA12 · Failures and notices reach the user anywhere

- **Given** `chooseEmulator('/x/Other.app')` failing twice with `notAnEmulator`, **then** `error` goes to that code, to null, and to it again.
- **Given** `/library` on screen, **when** the `SwitchBloc` emits `exited('Bodega Test', 1)` with a new `noticeId`, and then `error: switchGameRunning('/g/a.nsp', detail: 'DETAIL-7f3')`, **then** two toasts show `switchNoticeText(l10n, …)` and `l10n.errSwitchGameRunning('/g/a.nsp')`, in `en` and in `es`, and `DETAIL-7f3` shows nowhere.
- **Check:** `flutter test test/app/switch_bloc_test.dart test/app/pages_test.dart` (a case in the group "the routes").
