# Exploration · Game configurations (issue #16)

## Problem

Issue #16 asks for a configuration per game that makes it run well the first time:
- the backend, the sync mode and the runtimes;
- DLL overrides, registry values and variables.

It should cover as many games as possible, in three layers:
1. **curated** entries;
2. **automatic** ones, worked out from the game's own files;
3. results that **users report**.

In the app, it asks for:
- a Game configurations screen;
- a page per game;
- Apply with a preview, and Revert;
- a matched configuration applying by itself at launch, while what the user set by hand always wins;
- a clear warning when anti-cheat blocks a game.

The issue's acceptance criteria:
- **Everything shown is applied.**
- **Apply and Revert** work on both platforms.
- **Matching follows a set order:** Steam AppID or exe hash, then exe name or path, then title.
- **Unknown games** get an automatic configuration.
- **Coverage:** every catalog game, plus the most played Windows games that have a known Wine status.
- **Licenses:** each source's notice ships with its data.
- **Texts:** in both languages.

This change starts on top of `runtimes-and-performance` (issue #15), which is not committed yet. Its runtimes table is what a configuration's runtimes refer to.

## What exists today

### Per-game fixes (`packages/engine/lib/fixes.dart`)

- `GameFix`, `:57`, holds:
  - the game's Steam app id, or its exe file names;
  - steps of four types (`FixStep`, `:18`): `env`, `registry`, `dlloverride` and `ini`, each tagged with the platforms it was verified on;
  - `requires`, the runtime ids of `dependencyTable`;
  - `optIn`, notes, known issues and `verified`.
- **The data has two sources, read by `gameFixes`, `:120`:**
  - `fixes_data.dart`, generated by `tool/import_fixes.py` from highball-db's `recipes/games/` at commit `7a008d5`. It holds 20 fixes: 12 env steps, 18 registry steps and 2 DLL overrides, all for the Mac. Its `requires` are not imported.
  - `bodega_fixes_data.dart`, written by hand. It holds two fixes: Blur and Need for Speed: Most Wanted (2012).
- **Matching, `fixForApp`, `:161`:**
  - an app whose key is `steam:<appid>` matches by its app id;
  - any other app matches by its exe's file name;
  - there is no title matching and no hash matching.
- **At launch, a fix applies by itself and nothing asks** (`openApp`, `apps.dart:390-410`):
  - the fix's registry values are written;
  - the fix's variables and overrides go into the run's environment. The order is set at `engine.dart:291-310`: backend, then the game's fix, then the bottle, the program, sync and the launch itself.
  - An opt-in fix is never applied by itself.
  - An `ini` step is applied only by the user (`applyFixSettings`, `fixes.dart:342`).
  - When Steam is already open, a fix's variables can't reach the game. The log says so (`fixNotApplied`, `:185`).
- **The CLI** has `bodega fix list|show|apply` (`bin/bodega.dart:28-30`, `:169-181`).
- **The app shows no fix at all.** The only traces are the hint `hintFixNotApplied` and the line `depsFixOther` in the needs dialog.

### The automatic layer, which already exists in parts

- **Backend.** `resolveBackend`, `backends.dart:748`, picks the first of:
  1. the launch's option;
  2. the program's exception;
  3. the bottle's own setting;
  4. `auto`.

  On the Mac, `auto` comes from `autoBackend` (`platform_mac.dart:211`), which reads the exe's DirectX version and bitness (`exeGraphics`, `backends.dart:785`):
  - DX12 at 64 bits → D3DMetal;
  - DX10 or DX11 → DXMT, then DXVK;
  - anything else → Wine.

  On Linux the only backends are `wine` and `dxvk` (`platform_linux.dart:189`); there is no vkd3d-proton.
- **Runtimes.** `appNeeds`, `dependencies.dart:1222`, maps the exe's imports and the fix's `requires` to Bodega's runtimes. Since #15, these include .NET 4.8, the D3DX libraries, XACT, PhysX and the core fonts. The needs dialog offers them, and nothing installs by itself.
- **Engine.** Nothing detects Unity, Unreal or any other engine.

### Bottle settings (`backends.dart:399`)

`BottleSettings` holds:
- `backend` and `sync`;
- `programs`, a map from exe to that program's backend, env and HUD;
- `env`, `windows`, `dxvkAsync`, `avx`, `dlss`, `gpu`, `gamemode` and `user`.

Only what differs from the defaults is saved. The app shows the program exceptions (exe → backend) in `bottle_column.dart:554`.

### Catalog and anti-cheat

- **The catalog** (`catalog.dart:6`, `catalog_data.dart`) holds 7 installable apps from highball-db. Each has a backend, sync, env, registry, notes and known issues, and the app words them by id from the ARBs.
- **The anti-cheat list** is highball-db's `db/anticheat.json`, pinned at `f0bf6a2`. The app downloads it (`rest_client.dart:11`) and caches it in `cache/anticheat.json`. It shows on the catalog page.
- `antiCheatHints`, `catalog.dart:261`, detects Easy Anti-Cheat failing after a run.

## Data sources, measured on 2026-11-18

**highball-db** (CC0-1.0), at `bc72f85` of 2026-11-17. Bodega pins `7a008d5` for its fixes.

- **`db/games/`: 893 games, all for the Mac.**
  - 803 have a Steam AppID; 5 have an Epic app name; none has exe names or hashes.
  - **`status`:** 804 community, 49 blocked by anti-cheat, 21 verified locally, 18 reported upstream, 1 blocked by its publisher.
  - **`renderer`:** 243 dxmt, 123 d3dmetal, 32 dxvk, 13 wined3d, 1 vkd3d, and 481 with none.
  - **`anticheat`:** 63 games, each with names, a `macVerdict` and a note.
  - **Notes and known issues:** in English. The notes total 270 K characters and the provenance 369 K. The whole folder is 1.1 MB.
  - 16 games have `rendererResults`, a verdict per renderer.
- **`db/reports/`:** 1,203 user reports, with a rating from 1 to 5, the chip, the macOS version and the engine. They come in as GitHub issues through Highball's own form (`.github/ISSUE_TEMPLATE/report.yml`), which asks for Highball's version and engine id.
- **The engines in those reports:** Sikarugir's Wine 10 (959) and CrossOver's Wine (210), not Bodega's Wine 11. A renderer that worked there is a good lead, but it was not verified on Bodega.
- **`recipes/games/`:** now 47 recipes, against the 20 Bodega imported.
  - Their step types: note, environment, registry, renderer, file, dlloverride, copy, sync, and dxvkconfig.
  - Their `requires` name runtimes Bodega now has: `dotnet48`, `physx` and `corefonts`.
  - All 47 also name `steam`.
- **`db/derived/derived.json`:** 12,491 games, each with a ProtonDB tier and a "Mac prediction". It is **ODbL-1.0**. Its own note: "NOT a macOS verification".

**umu-protonfixes** (BSD-2-Clause), on `master` as of 2026-11-18.

- **Its scripts:** 320 for Steam games, 80 for GOG, 29 for Epic, and a few for other stores. They are Python.
- **What the Steam scripts call, by count of calls:**

  | Call | Count |
  |---|---|
  | `protontricks` | 285, in 171 scripts |
  | `set_environment` | 47 |
  | `winedll_override` | 42 |
  | `replace_command` | 37 |
  | `regedit_add` | 33 |
  | `append_argument` | 29 |

- **The most common protontricks verbs:**
  - `d3dcompiler_47` (33), `vcrun2019` (17), `physx` (10), `d3dx9*` (15), `dotnet48` (6) and `d3dx11_43` (6) map to Bodega's runtimes.
  - `d3dcompiler_43` (21), `directplay` (14) and `dsound` (8) have no runtime in Bodega.
- **It is written for Proton on Linux:** many variables are `PROTON_*`.

**Whisky's fork** (GPL-3.0) has 83 games, most of them inferred recipes that nobody tested (according to its own AUDIT.md). It is the only source with exe fingerprints.

## Project constraints

- `fixes_data.dart` is generated by `tool/import_fixes.py` and is never edited by hand. Bodega's own entries go in `bodega_fixes_data.dart`, each with how it was verified.
- **Data ships as Dart text, not assets:** `dart compile exe` carries no assets. 893 games come to about 1.1 MB of JSON, or about 0.5 MB without the provenance.
- **The data's own sources:**
  - highball-db, only at a pinned commit;
  - never `umu-database` (GPL-3.0, a project rule);
  - nothing from CrossOver, PCGamingWiki or Lutris.
- Never help get around anti-cheat. Only warn about it.
- **Text rules:**
  - What the user reads comes from the ARBs.
  - `domain/` and `data/` hold no user-facing words.
  - Notes as long as highball-db's (893 games, in English) can't go into the ARBs.
- Agents run Wine only headless. Testing a game is the user's job.
- Everything under `.sdd/` and in git is in English.

## Open questions, for propose

1. **The Mac's data.** Import highball-db's `db/games/` (893 games) and the 47 recipes at a new pinned commit, with their `requires` mapped to Bodega's runtimes? *Recommended:* yes. It is CC0, it covers far more than any other source, and it brings user reports. Each entry would be shown as "community (Highball)" until it is verified on Bodega.
2. **Linux.** *Recommended:* in this change, Linux gets only the automatic layer and Apply/Revert. umu-protonfixes, which is Proton-specific and stored as Python, would come in a later change, keeping only the verbs, variables and overrides that apply to plain Wine.
3. **ODbL's `derived.json`** (12,491 predictions) and **Whisky's GameDB** (83 untested games). *Recommended:* neither, for now. They hold predictions and unverified data, and ODbL would ship as a separate database with its own notice.
4. **Where users' reports go.** *Recommended:* Bodega opens a prefilled GitHub form in Bodega's own repo, in the browser, and the user sends it with their own account; Bodega has no server. Bodega also keeps the user's verdict locally for each game. Reports become curated data by hand, in `bodega_fixes_data.dart`. Sending them to highball-db instead would need its maintainer's agreement, because its form asks for Highball's version.
5. **The language of highball-db's notes.** *Recommended:* show them in English under a label that says so, as the CLI does. Everything Bodega words itself (statuses, steps, warnings) goes in the ARBs. This bends the Text rule for third-party data only, and needs your approval.
6. **Apply and Revert.** *Recommended:* the configuration is a layer resolved at each launch, as fixes are today, and is not written into the user's settings:
   - **The backend's order:** the launch's option, the program's exception, the bottle's own backend, then the configuration, then `auto`. What the user set by hand wins.
   - **"Revert"** becomes a per-app switch, "Use this game's configuration". Turning it off also deletes the registry values the configuration wrote.
   - **The preview** comes from the same function the launch uses, so what is shown is what is applied.
   - **Runtimes** are proposed in the needs dialog, as now, and never downloaded by themselves.
7. **Matching.** No source has exe hashes except Whisky's.
   - *Recommended order:* Steam AppID, then exe name (Bodega's own entries and the catalog's), then the title, after normalizing it (lowercase, without symbols, ™ or ®), for games added by hand.
   - A match by title is shown as "matched by name", so the user can check it.
8. **Size and milestones.** *Recommended:* four milestones.
   - **M1, engine:** the import, the model, matching, the launch layer and the CLI.
   - **M2, app:** the screen, the game's page and the per-app panel with its switch.
   - **M3:** reports.
   - **M4:** checks on both platforms.
