# Exploration: dependencies

## Problem

The user's request (2026-11-16): whenever a game or any program goes into a Bodega bottle, Bodega checks it and **proposes** installing the Windows dependencies it needs. This is issue #15 (a Dependencies panel per bottle) and the automatic layer of issue #16 (work out what a game needs from its own files), plus one more kind of per-game fix that the two cases below showed.

Two real cases from the user's `Games` bottle (macOS, runtime `engine-wine-11.0-20261030T202616Z-primer-build`) are the targets:

| Game | What was wrong | What fixed it, by hand | Kind of fix |
|---|---|---|---|
| Blur (`Blur.exe`, 32-bit, D3D9) | Crashed now and then in Wine's builtin `msvcr90.dll` (`sin`/`cos` → `__rem_pio2` with a huge argument, with the x87 precision set to single by D3D9) | Microsoft's own VC++ 2008 CRT (9.0.30729.6161) for `Blur.exe` only: its DLLs in `windows/winsxs/x86_microsoft.vc90.crt_1fc8b3b9a1e18e3b_9.0.30729.6161_none_deadbeef/`, and `HKCU\Software\Wine\AppDefaults\Blur.exe\DllOverrides` `msvcr90`, `msvcp90` and `msvcm90` set to `native,builtin`. Wine's copies are in `~/Library/Application Support/Bodega-backup-2026-11-12/games-vc90-wine`. A 73-minute session followed with no crash and no `msvcr90` error in the log. | A missing runtime: **vcrun2008** |
| Need for Speed: Most Wanted 2012 (`NFS13.exe`, 32-bit, D3D11) | Sound stutter: the game's own audio engine (EAAudioCore 8.03, x87 code) keeps one core at 95–100% under Rosetta and falls behind its DirectSound buffer | `[Sound] Reverb=0` instead of `1` in `~/Documents/Criterion Games/Need For Speed(TM) Most Wanted/config.NFS13Save` (CRLF line ends). Measured: 95 "Overwriting mixing position" warnings in 71 s before, 6 in 190 s after; the audio thread dropped to about 12%. The user confirmed the sound is clean. | Not a runtime: a **setting in the game's own file** |

Both fixes live only in the user's files today: removing the bottle brings Blur's crash back, and any other Mac has both problems.

## What the user's games import

A scan of the import and delay-import tables (scratch script, not in the repo):

| Program | Bits | SxS manifest | Imports that matter |
|---|---|---|---|
| `Blur/Blur.exe` | 32 | `Microsoft.VC90.CRT` 9.0.21022.8 | `msvcr90.dll`, `d3dx9_42.dll`, `xinput1_3.dll`, `binkw32.dll` (ships in the game folder) |
| `NFS13.exe` | 32 | none | `d3dcompiler_43.dll`, `xinput1_3.dll` (no VC++ runtime: linked statically) |
| `plutonium.exe` | 32 | none | `mscoree.dll` only: a .NET program |
| `LanLauncher.exe` | 64 | none | system DLLs only |

Wine provides `d3dx9_42`, `d3dcompiler_43`, `xinput1_3` and `mscoree` (through Wine Mono 10.4.1, which the runtime ships in `engine/share/wine/mono`) as builtins, and they usually work. Of these games only Blur needed a Microsoft runtime, and it imports `msvcr90` through a manifest that Wine's own builtin assembly (`..._9.0.30729.6161_none_deadbeef`) also satisfies, so "the import is satisfied" never meant "it works".

## What Bodega has today

### Engine (`packages/engine/lib/`)

- **Per-game fixes** (`fixes.dart`): `FixStep` accepts only `env`, `registry` and `dlloverride` (`fixes.dart:21`), each with `platforms`. `GameFix` has an `optIn` flag, notes and known issues (`fixes.dart:35-80`). A fix is found only by Steam app id: `fixForApp` reads `steam:<appid>` keys and returns null for anything else (`fixes.dart:105-108`), so Blur and NFS13, added as custom programs, can never get one.
- **Where fixes apply**: at launch only, in `openApp` (`apps.dart:390-395`): registry steps through `reg add` (`_applyFixRegistry`, `fixes.dart:166-182`), env and DLL-override steps into the launch environment (`engine.dart:290-312`).
- **Fix data** (`fixes_data.dart:1-6`): generated by `tool/import_fixes.py` from highball-db at commit `7a008d5` (CC0), 18 games; the project rules forbid editing it by hand. `convert()` keeps `note`, allowed `environment`, `registry` and `dlloverride` steps and drops every other step type (`tool/import_fixes.py:55-72`). It ignores highball-db's `requires` field and its `recipes/tweaks/` folder.
- **Adding a program**: `addApp` (`apps.dart:133-170`) registers `custom` apps in `apps.json`, with the exe relative to `drive_c` or an absolute host path (the user's games are all absolute paths under `~/Documents/Games/`). The catalog's installers register theirs through `_registerApp` (`catalog.dart:220`). Shortcut apps (`apps.dart:282-314`) and Steam games (`apps.dart:320-353`) are **detected** each time the list is read (`_appsIn`, `apps.dart:228-249`): nothing records when they appeared, so "a program was added" has no single event today.
- **Reading an exe**: `exeGraphics` (`backends.dart:774-812`) scans the raw bytes for D3D DLL names, in another isolate, because imports alone miss `LoadLibrary`; `_peBits` (`backends.dart:815-832`) reads the PE machine. Nothing parses the import table.
- **Downloads**: `_download` (`backends.dart:330-367`): curl, HTTPS only, resumable, into `$home/downloads/`, checked against a pinned SHA-256, and skipped when a matching file is already there. It names the file after the URL's last segment unless `name:` is given: every VC++ redistributable is called `vcredist_x86.exe`, so names must be given. `sha256Of` (`backends.dart:370-373`).
- **Running things in a bottle**: `_launchIn` (`engine.dart:230-330`) with `backend: 'wine'` and a `label`, then `exitOf` (`engine.dart:350-358`); `backendTest` (`backends.dart:895-938`) shows the pattern with a timeout and `stopBottle`. `reg add` runs the same way (`fixes.dart:168-180`). Every process gets `wineEnv` (`engine.dart:67-83`), and `WINEDEBUG` can come from `BODEGA_WINEDEBUG`.
- **Failures**: 30 final `EngineFailure` subclasses (`failures.dart`), among them `MissingFile`, `ChecksumMismatch`, `CorruptData`, `NotDownloadable`, `WineToolFailed` and `ProcessFailed`; `WineTool` (`failures.dart:435`) names the tools whose exit codes are reported.
- **CLI** (`bin/bodega.dart:6-41`): `fix list` and `fix show` print the fixes; there is no `add` command (the app adds programs).

### App (`apps/bodega/lib/`)

- **Bottle page**: `BottleDetailView` (`app/presentation/bottles/bottle_detail_page.dart`) shows the apps in the center and `BottleColumn` at the right, whose collapsible sections are Settings (`bottle_column.dart:373`), Tools (`:526`), Gamepads (`:539`) and Details (`:540`). A Dependencies section fits beside them.
- **Adding a program**: the add-app dialog (`app/presentation/add_app/add_app_dialog.dart`, 499 lines) and `AddAppRepositoryImpl.addApp` (`data/repository/add_app_repository_impl.dart`), which calls `engine.addApp` and returns the app's key. That is where a scan can start for user programs.
- **Downloads with progress**: the app downloads through `Downloader` (`data/service/downloader.dart`, HTTPS, resumable, cancellable) and hands the file to the engine, which checks its checksum: `BackendRepositoryImpl` does it with `engine.installBackend(..., tarball:)` (`data/repository/backend_repository_impl.dart:51-86`).
- **Fixes in the app**: none. The per-game fixes apply silently at launch and are never shown; the catalog shows only its launchers' known issues (`app/shared/text/catalog_text.dart`).
- **Text**: 409 keys in `lib/l10n/app_en.arb`, mirrored in `app_es.arb`; errors are `AppError` codes worded in `app/shared/text/`.

### Runtime

The installed runtime has no `winetricks` and no `cabextract` (searched `runtimes/engine-wine-11.0-…` to depth 4). It ships Wine Mono 10.4.1 and Wine Gecko 2.47.4. The Linux packages don't list `cabextract` either (`packaging/linux/build_deb.sh:36-37`, `packaging/arch/PKGBUILD:12-13`).

## Where dependency data can come from

**highball-db** (CC0, the source Bodega already imports): at the pinned commit it has nine tweaks in `recipes/tweaks/`: `concrt140-native`, `controller-sdl`, `corefonts`, `dotnet48`, `fakejapanese`, `flight-controls-raw-hid`, `physx`, `vcrun2022` and `xact`. Their steps are typed:

- `installer`: a URL, its SHA-256, silent arguments and a label. `vcrun2022` is two of these (`VC_redist.x64.exe` and `VC_redist.x86.exe` with `/install /quiet /norestart`), plus `registry` steps that set `Version=win10` for the installers and `native,builtin` for the VC++ 2015+ DLLs.
- `winetricks`: verbs, and a `slow` sentence with the size and the time (`xact` says about 100 MB and a few minutes). `xact`, `physx`, `dotnet48`, `corefonts` and `fakejapanese` are this kind; their `lastVerified.result` notes that `xact` was checked "with the app's bundled cabextract".
- `note`, and a `lastVerified` block with date, engine, macOS, chip and result.

Game recipes name what they need in `requires` (for example `toram-online` requires `steam` and `fakejapanese`). Its game database matches by Steam app id only: no exe names, so no non-Steam game such as Blur or NFS13 can match.

**winetricks** (LGPL-2.1-or-later; version `20260125-next` read on 2026-11-16): VC++ 2005, 2008, 2010, 2012 and 2013 are each "download Microsoft's `vcredist_x86.exe` (and `vcredist_x64.exe` for 64-bit prefixes), check its SHA-256, run it with `/q`, set `native,builtin` for its DLLs". None of them needs `cabextract`. For vcrun2008 that is `atl90 msvcm90 msvcp90 msvcr90 vcomp90`, from `https://download.microsoft.com/download/5/D/8/5D8C65CB-C849-4025-8E95-C3966CAFD8AE/vcredist_x86.exe`, SHA-256 `8742bcbf24ef328a72d2a27b693cc7071e38d3bb4b9b44dec42aa3d2c8d61d92`. The DirectX extras (`d3dx9`, `xact`) unpack the June 2010 redistributable (about 100 MB) with `cabextract`. `dotnet48` removes Wine Mono, installs `dotnet40` first and changes the Windows version. Microsoft sometimes replaces a file at the same URL, so pinned checksums go stale (Winetricks/winetricks#2195, cited in #15).

**The imports themselves** (#16's table, plus the older CRTs): `msvcr80`/`msvcp80` → vcrun2005, `msvcr90`/`msvcp90` → vcrun2008, `msvcr100`/`msvcp100` → vcrun2010, `msvcr110`/`msvcp110` → vcrun2012, `msvcr120`/`msvcp120` → vcrun2013, `vcruntime140`/`msvcp140` → vcrun2022, `mscoree` → .NET, `d3dx9_*` → d3dx9, `xactengine*`/`xaudio2_*` → xact, `physxloader` → physx. A manifest dependency (`Microsoft.VC90.CRT` in Blur) names the CRT even when the import table alone would not say which build it wants.

## Constraints from the project

- Everything in git is in English, `.sdd/` included; Spanish only in the ARBs and the `.lproj` files (`.claude/CLAUDE.md`, "Language").
- `fixes_data.dart` is generated: Bodega's own entries (Blur → vcrun2008, NFS13 → `Reverb=0`) need another home, or have to go upstream to highball-db first.
- Microsoft's installers are never stored in the repo or in Bodega's packages (#15); they come from Microsoft's servers, checked against a pinned SHA-256, and cached in `$home/downloads/`.
- Agents run Wine headless only: checking that Blur stops crashing with the new install, and that NFS13 still sounds right, is the user's job, in `verify`.
- Never follow symlinks inside a bottle (`dosdevices/z:` is `/`). The NFS13 file sits behind one: the bottle user's `Documents` folder is a link to the host's `~/Documents`.
- Layers: only `data/` imports the engine; errors are codes; a new `EngineFailure` needs its English message, a case in `english_test.dart`, a case in `appErrorOf` and its words in `app/shared/text/` (`.claude/rules/architecture.md`).
- Versioning: a feature raises the minor version. `main` is at `1.6.0+14`; pull request #20 (`feat/switch-keys-firmware`, `1.7.0+15`) is still open. This change raises one minor above whatever `main` holds when it is branched.
- Slow links (the user and many users are on one): show each download's size, never fetch what is not needed, resume downloads, and accept a file the user already has, checked against the same SHA-256, as `installBackend(tarball:)` and `installSdl(dmg:)` do.
- Linux: the same engine code runs there; whatever the Mac needs (a tool, a download) has to exist on Linux too, or the item is marked as Mac-only.

## Open questions for `propose`

1. **How to install.** Only `installer` and `registry` steps in this change (the VC++ family and vcrun2022, no new tool), and `winetricks` steps later, once Bodega ships winetricks and a `cabextract` for both hosts? Or winetricks for everything now?
2. **When to propose.** After "Add program" and after a catalog install there is a moment; Steam games and shortcut apps are only detected. Propose for those when the bottle page opens, and remember what was already proposed or dismissed per bottle?
3. **Recommended or optional.** Recommended only when a curated entry says so (a Bodega entry for the exe, or highball-db's `requires` for a Steam game), optional when only the imports point at it? Should optional items hide the runtimes Wine already covers well (`d3dx9`, `xinput`, `d3dcompiler`, Mono for .NET)?
4. **Scope of the overrides.** Bottle-wide `native,builtin` (winetricks, highball-db) or per program (`AppDefaults\<exe>\DllOverrides`, as Blur's manual fix)? Bottle-wide affects every program in the bottle.
5. **Where Bodega's own curated entries live.** A new hand-written data file in the engine, a local JSON that `tool/import_fixes.py` merges, or recipes sent to highball-db first?
6. **The settings-file step.** Apply it once when the user accepts, or before every launch? The file only exists after the game's first run, and the user may change the setting back in the game's own menu.
7. **Matching non-Steam games.** By exe file name (`blur.exe`, `nfs13.exe`), or name plus size or PE timestamp?
8. **"Installed".** Read from the prefix (Microsoft's DLL in place, not a Wine builtin) rather than from a button press, so that a runtime a game's own installer added also counts?
9. **Out of scope?** Uninstalling a dependency; #15's performance options; the Wine patch for `__rem_pio2` (it would mend Blur without Microsoft's DLL, and other D3D9 games that hit Wine's `msvcrt` or `ucrtbase`).
10. **Branch.** From `main` once pull request #20 is merged, or on top of `feat/switch-keys-firmware` now?
